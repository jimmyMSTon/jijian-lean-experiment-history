从包含 Native 修复的独立 Git 分支 codex/v2-native-lifecycle-qa（bbb251a）构建完整 SwiftUI 测试包，使用与起点 d9ba067 完全相同的打包后端。

## 真实 GUI 操作结果

1. 系统应用菜单“证明 → 我的证明”可正常打开历史 Sheet，列表只包含独立数据库内 1 条 V2 记录。
2. 点击该记录可以完整取回原稿和 V2 Kernel 证据。历史日期从 ISO 原始串转为中文本地时间。
3. 修复前：存档 fixedStatementKernelPassed=true、originalRouteKernelPassed=true，两步骤 passed，但由于模型在 MathIR 中保存一条“乘法单位元律未明确量化范围”的解释提示，客户端选错红色未完成页面；同一屏显示 2/2 已核验、内核已核验、当前数学解释尚未通过、原文歧义 0 与 1、V2 已保存与暂无记录等矛盾信息。
4. 修复后：使用同一份 Kernel 真证书和 MathIR，从真实 GUI 重开历史，进入已验证页面，清楚显示“形式化原证明路线已通过 Kernel；原稿有 1 处解释待核对”，两步骤已核验，第二步使用第一步依赖。原稿解释内容单独完整显示，仍不宣称 Lean Kernel 证明原文语义等价。
5. 在实际结果页面按“返回原证明继续编辑”，AX TextEditor 中原稿全文无损恢复。通过 GUI 辅助接口修改文字后，编辑页面及时显示“新增 1 行、移除 1 行”；后台不自动再提交模型。隔离数据库任务数仍为 1 条 completed。
6. 正常使用 App 的 Quit 菜单退出后，该 App 和其独立后端都退出，没有残留 Lean/后台服务进程，前台焦点回到启动前的原应用。

## 独立异步 HTTP 合同测试

tests/native_v2_job_lifecycle.swift 与 tests/run_native_job_lifecycle.py 编译实际 NativeStore，通过 URLSession 连接真实本地延迟 HTTP 模拟服务。测试过程中用户修改已提交原稿并再次点击验证：只产生 1 次 POST，接受的旧任务 ID 不丢失，旧结果不能覆盖新稿，取消请求只有 1 次；MathIR 结构失败正确标记“尚未运行 Lean”，不被当成数学错误。无模型调用。

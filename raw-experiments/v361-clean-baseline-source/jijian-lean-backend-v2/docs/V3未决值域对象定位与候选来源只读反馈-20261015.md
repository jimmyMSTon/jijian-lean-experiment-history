# 极简 Lean V3｜未决数学值域的对象级来源定位与只读反馈

日期：2026-10-15
基线：正式开发分支及 main 的 cc6393e058ba131d09823644304ddd4aaf5cce58。

## 发现的 Native 产品缺口

已有的 V3 MathIR 将尚未授权的数学载体保留为 TypeVar，后端在锁定 Lean 命题前保存 mathir_v2_draft 并返回 MATHIR_V2_INVALID / V2_TYPE_DOMAIN_UNRESOLVED / clarificationRequired.kind=mathematical_value_domain。

Mac Native cc6393e 已实现“需要确认数学值域”的通用告知，却没有从后台的 clarificationRequired.typeVariables 及保存 MathIR 声明中展示究竟是哪一个对象需要核对、原稿关联的具体片段，以及模型是否记录了可能数域。用户无法直观看到下一步应该核对哪段原文。

## Native 改动和可信性边界

1. NativeV2StructureFailureEvidence 增加只读 pendingDomainReviews。必须同时满足 error.validationCode、clarificationRequired.kind、draftId、草稿 validated=false、草稿 validation.code，且 error 与保存草稿中的每一条 typeVarId/path/declarationId/candidateKinds 完全匹配；任何草稿 ID 或数据不一致都不展示特定的数学对象，保留已有通用诊断。
2. 对符合以上规则的同源对象，读取保存的声明 name/ID；每一个 SourceRef 必须有唯一 blockId、严格 Unicode scalar 半开索引范围，不得因重复块或错误越界而捏造图片位置。没有可靠映射不显示来源片段。
3. 候选仅显示为“模型候选数域（未确认）”，从明确白名单映射 Nat/Int/Rat/Real/Complex 为 ℕ/ℤ/ℚ/ℝ/ℂ。候选为其他类型、缺失或并非完整可显示时明确表示尚未确定，不默默填入 Real/Rat。
4. NativeSystemError 展示具体待确认对象/原稿片段/MathIR path。只有当前单份识别记录仍在 NativeStore 时才展示“返回识别校对”的交互，其他输入引导用户自行核对并明确补充数学条件。
5. 本轮不更改后端 MathIR、原稿、原图、类型推断、SourceRefs 或 Lean/Kernel 判定，也不引入新的 Provider 请求、重试配额或系统 Gate。页面的候选数域不是建议用户任选，也不代表系统已经取得合法数域声明。

## 测试与证据

- 实际 Swift BackendClient + NativeV2StructureFailureEvidence 单元可执行测试：候选 Rat/Real 显示但不自动确认；ID/路径/候选被篡改时不渲染；重复 SourceBlock ID 不伪造来源；未知候选不强制选择；通过。
- 真正的 Swift NativeStore + BackendClient + localhost mock Server 异步任务覆盖 V2 作用域失败、旧草稿读取竞态及 V3 值域未决失败。3 次接受模拟提交、3 次仅读后端已有草稿 artifact，返回原稿编辑后诊断全部清除，不重复提交或触发模型，实际 PASS。
- 该模型不含真实 DeepSeek/视觉请求；不属于学生原数学证明 Kernel 结果。完整 SwiftUI typecheck、隔离签名 App 启动与 GUI 操作须另外运行并分别记录实际结论。

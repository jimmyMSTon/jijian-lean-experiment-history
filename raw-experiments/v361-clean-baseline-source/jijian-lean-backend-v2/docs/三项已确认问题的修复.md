# 三项已确认问题的修复

本次只使用原有代数、奇数求和归纳、三角多项式三题，不扩大样本。模型、Statement Lock、Binder Map、Statement Hash、Mathlib 检索与数据式 Kernel 复核机制保持原有配置。

JSON 由 `backend/providers/json_parser.py` 确定性解析，禁止重复键和非有限数值。可恢复项仅包括完整 Markdown 围栏、末尾多余逗号，以及解析器确切指出的连续多余右花括号；不补值、不截断响应、不改数学字段。恢复后必须通过完整 JSON Schema。无法恢复返回 `PARSE_ERROR` 并保存未验证响应，解析过程没有 Provider 重试。原始代数真实响应中的六个多余括号已保存为显式 recorded fixture。

MathIR 增加 `inductions`，明确引用 variableId、baseCaseId、hypothesisId、stepCaseId、conclusionId、stepScopeId。假设节点是归纳子作用域的 Claim；基础情形是 P(0)，后继情形是 P(n+1)，总结是 ∀n,P(n)。验证器检查 AST 与作用域，拒绝把局部归纳假设当作全局待证明步骤。Compiler 仅在该子作用域引入假设，总目标没有新增外部前提。没有归纳结构的旧记录序列化保持不变，因此已有三角题 Statement Hash 不变。

Repair 只替换当前 `localVerified=false` 的片段，保留全部已通过片段的原文与 hash。依赖未完成但自身已通过的片段不再重写。真实 Lean 明确报告 flat `use ...; exact ...` 的第二句 “No goals to be solved” 时，成功前缀被显式锁定，模型只能删除多余的末尾 tactic；其余修复仍由实际 Lean diagnostics 驱动，最终照常进行真实 Kernel 复核。

`check_three_confirmed_fixes.py` 是这三题的单次接续工具：恢复原始真实 JSON、显式迁移已审阅归纳假设的角色、复用三角题原有 8 个成功片段。它不把 fixture 自动装进正式 Provider。新的真实 proof/repair 请求沿用审计、开发缓存和 single-flight，没有新增网络开关或请求次数限制。

## 本轮发现并修复的跨层契约缺陷

1. V3 MathIR 的 goal.sourceRefs 缺失/损坏时，证明报告之前使用 ProofRecord.goal 的全原稿 normalized 兜底，并错误冠以「待证命题（来源文字）」。现在只在存在可用源区间时标记为对应原稿；否则从类型化 MathIR goal.expression 生成只读数学表示，明确标注模型结构化解释及其尚无可靠原稿位置。不能将全文当成待证目标，也不以 Kernel 通过证明来源等价。
2. NativeMathIRContext.sourceExcerpt 以前只检查 Unicode scalar 半开区间，可能把一个由多个 scalar 组成的 Emoji 或组合重音截成不可读的来源片段。现在先检查字符完整边界，裂开的复合字符拒绝作为可靠来源，高亮依然不猜图像像素坐标。
3. 旧保存记录若出现重复 proofRoutes ID 或重复 route node ID，ProofRecord.v2Rows 过去取第一个并显示关联来源/依赖，可能误配不同证明路线。现在仅使用唯一匹配的来源路线和节点，发现重复时给出对应歧义提示；dependsOn 只有唯一真实目标节点才补 route 前缀。
4. 历史 verify route 中若同一复合步骤身份保存了两个 expectedType，ProofRecord.formalType 以前默默返回第一个，导致证明详情可能展示不属于当前步骤的 Lean 命题。现在仅当复合步骤身份恰有一个记录时返回其 Lean 核验目标，否则不冒称存在唯一对应。

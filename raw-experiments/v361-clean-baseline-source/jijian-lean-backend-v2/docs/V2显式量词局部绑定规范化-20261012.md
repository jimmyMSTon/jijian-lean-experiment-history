## 通用修复

在 MathIRV2Service.structure 的严格编译/statement lock 之前：
- 遇到明确声明 targetType 的 forall / exists 词法绑定，但 model 忘记独立 Declaration，确定性地 materialize 该 ID 和已声明的类型。
- 声明创建在量词所属步骤 scope 的专门子 scope；不会跑出独立步骤成为新的 theorem/local hypothesis，也不会改变锁定 Goal 或来源原文。
- 原先错误把 binderId 放在 symbol 节点的写法，仅在实际词法量词范围内转为同一 ID 的 symbolId，且保留归一化记录。
- 将该量词已经明确给出的 targetType 复制到 declaration 后移除量词上的冗余字段（MathIR v2 仅 ascribe/cast 可以带 targetType），不猜测类型。
- 不带显式类型的未知量词仍拒绝；symbolId/binderId 冲突和新变量 ID 被不同量词重复使用时仍拒绝。
- 所有 normalizations 持久化并标明原因，source raw、Goal、sourceRefs、dependsOn、Mathlib 证据与 Kernel 成功语义不变。

修改：backend/v2/source_normalization.py、backend/v2/service.py；新增测试 tests/v2/test_explicit_quantifier_binders.py（6 case）。

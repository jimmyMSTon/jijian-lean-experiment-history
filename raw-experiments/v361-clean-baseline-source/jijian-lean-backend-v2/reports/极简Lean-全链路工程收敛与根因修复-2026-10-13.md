## 已实施的本轮改动

### 提示词来源证据组织

新增 `backend/v2/prompt_source.py`，为模型请求生成可解析的来源视图：相同的 raw、normalized 和 block text 使用 `sameAs` 引用；来源块仍带稳定 block ID 与原位置元数据。它只影响送给 Provider 的 payload，持久化 MathIR、sourceRefs、原文、Statement Lock 和 Binder Map 不变。

`backend/v2/structure.py` 在结构化提示中仅移除非语义的来源摘要哈希、识别记录 ID 和固定契约说明字段；结构响应仍由服务端重建完整 source provenance。`backend/v2/proof_only.py` 将本次 obligations 依赖的原文证据集中发送，保留 sourceRefs、完整 MathIR 关系、依赖、expected type、ambiguous/correction 信息、diagnostics 与 Mathlib 证据；不再把同一来源切片同时重复放进 obligation、dependency 和 originalStep。没有删除或截断候选数学证据。

采用保存的真实 smoke 输入做离线 JSON body 字节重建，而非再调用模型：结构请求减少 27 字节（0.20%）；单 obligation proof-only 请求增加 449 字节（8.56%）。因此这组简单单步骤样本没有证明 Token 或成本下降；结构去重对多 obligation / 多依赖提示词可能减少重复片段，但尚无同条件、多步骤的实测节省证据。实际 Token 仍以 Provider usage 为准。本轮不将该结果宣传为成本优化。

### 调用审计

`backend/providers/deepseek.py` 将 Provider 返回的 `completion_tokens_details.reasoning_tokens` 写入现有审计事件；不记录 key、模型私有 reasoning 内容或请求正文。`scripts/run_mathir_v2_novel_audit.py` 将该数字纳入导出记录。`tests/test_ai_audit.py` 验证记录包含推理 token 数值、仍不包含 reasoning 文本或密钥。

### N01 结果保全和 N02 停滞控制

N01 结果异常已由当前整合基线中的通用修复覆盖，而不是通过本轮专门写死 N01：Kernel 结论先持久化；资源指标来自真实 verification history / Runner `.metrics` 接口；指标缺失或审计脚本中断另记为研究脚本错误，不覆盖已有数学结果。`run_mathir_v2_novel_audit.py` 的通用测试涵盖成功结论、附加指标缺失和中断恢复。

N02 历史数据来自 `reports/interrupted-live-audit-20261012/`：41 次真实请求，其中 mathir 1、formalization 1、repair 21、LibraryPlan 18；输入 6,231,817 tokens、输出 177,902 tokens，耗时 1,876.834 秒。41 次 `retry_index` 全为 0，input hash 均不同，故不是网络 retry 或相同请求复发。危险增长来自 workflow 每轮交错 LibraryPlan 与 Repair、累计检索上下文，以及仅按完整 payload hash 判断新旧。

整合主线中的 `backend/v2/workflow.py` 已改为先向当前固定 obligation 要 proof，再交真实 Lean/Kernel；证明通过时不先做 Mathlib 检索。只有 Lean 提供失败诊断后才评估确定性 cleanup 和检索。repair state 指纹基于锁定命题、obligations、失败类型和稳定诊断、Kernel 步骤证据及依赖闭包，而不是 proof 文本或完整 prompt hash。相同实质状态再次出现且没有新 Lean / Kernel / Mathlib 可操作证据时，以 incomplete/stalled 结果结束；没有固定轮数、Token 上限、难度门槛或 live 开关。完整检索记录仍持久化，Repair Prompt 只关联当前失败 obligation 的检索 scope，并做确定性去重；历史证据不因上下文缩小而删除。

deterministic cleanup 在 AI 检索前执行，并通过真实 Lean 重核；它不跳过原证明依赖，也不更换 statement。已有完整通用回归覆盖：缺 proof 时 proof-first、重复数学状态停滞、诊断变化后允许继续、cleanup 顺序、保留完整检索历史、仅向 Repair 提供当前相关证据。N02 没有同条件修复后真实模型对照，因而不能报告其请求数、Token 或耗时的实测改善比例；本轮没有为取得比例重跑 N02。

## 尚存的真实问题

1. MathIR 的表达语言仍是封闭 Typed AST；任意高阶函数、自定义对象或一般函数应用不能自动表示。责任在 `backend/v2/models.py`、`compiler.py` 的当前表达契约。不能放宽 Binder/类型/Statement Lock 来伪装支持。
2. 语法、类型和 Kernel 正确不代表原文与 MathIR 语义相同；该语义对应仍需可审查的来源与翻译契约。责任在结构化翻译及来源证据，不属于 Lean Kernel 能自动证明的范围。
3. N02 的停止机制已有通用 fixture/test 与状态指纹，但没有同条件、修复后的真实 DeepSeek 成本对照；不得据此宣称 41 次已经在相同题目上降为某个数字。
4. 新鲜 smoke 只走纯文本简单归纳等式，未触发 Mathlib/Repair/OCR；完整视觉和修复闭环本轮未做 live 验证。
5. 已安装最终提交构建的 App，但当前运行中的旧实例没有被关闭或重启；完全退出旧实例后重新打开 `~/Applications/极简 Lean.app` 才会运行这次安装的二进制。用户归档 App 未触碰。GUI 自动化验收使用隔离 QA 包，尚未对刚安装的最终 App 实例做摄像头、手写/PDF 输入等 live GUI E2E。

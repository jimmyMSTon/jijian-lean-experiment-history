# 真实证明盲测请求审计中断计数加固（2026-10-14）

## 根因

盲测入口 `_safe_audit_rows` 只导出 `phase=finished` 的 Provider 事件。正常返回、供应商错误和 Python 可捕获的取消会写结束事件；进程被中断在请求开始与结束之间时，只剩 `started` 的请求会从汇总中消失，错误地表现为零请求。`backend/ai_audit.append` 也没有在写入后 `fsync`，因此开始请求记录尚未保证落盘。

## 修改

- `ai_audit.append` 在写入每条开始/结束事件后同步文件描述符，保护请求边界记录。
- 盲测报告按 `request_id` 合并开始与结束事件；只有开始记录的请求保留为 `started_only`，标记 `attempt_started_no_terminal_record`，不会和“未请求”混为一谈。
- `providerUsage` 现在分别统计实际 Provider 尝试、模拟传输、调用类型未知、审计未闭合和输入/输出 Token。导出仍使用字段白名单，不包含 API Key、prompt 或响应正文。
- 文档说明了强制终止时的边界：同步审计及逐阶段证据保留，但进程不能运行 `finally` 时不会自动生成完整 `blind-result.json`。

## 验证

- 盲测审计和 Provider 审计定向测试：**15 passed**。
- 全非 live 回归：**476 passed，24 deselected，1 条 Starlette/AnyIO 弃用警告**；`compileall`、`git diff --check` 通过。
- 本轮未访问 DeepSeek、未运行 Lean/Kernel；没有模型请求或 Token 消耗。本改动仅涉及审计和盲测记录，不改变正式数学判定。

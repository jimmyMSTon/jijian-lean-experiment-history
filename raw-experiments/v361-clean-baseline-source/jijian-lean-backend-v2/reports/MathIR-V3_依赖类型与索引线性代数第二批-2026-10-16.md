## 本批实现

`TypeApplication` 现在同时承载类型实参和值实参：

- `typeArguments`：类型实参。
- `termArguments`：普通 MathIR 表达式形式的值实参。
- `argumentOrder`：可选的 `type`/`term` 顺序表，允许两类参数交错；省略时按类型实参在前、值实参在后的顺序解释。

例如 `Fin n` 用一个值实参表示；`Vector α n` 用类型和值实参表示；`Finset (Fin n)` 将 `Fin n` 作为外层的类型实参。值表达式继续走现有声明 ID、作用域和类型检查，不接受任意 Lean 源码。Schema 递归定义、结构化提示词和两份 MathIR v2 JSON Schema 已同步。

依赖类型检查不止解析参数：它检查值实参在声明作用域中可见且可推类型，将维度符号纳入声明拓扑排序和循环检测，并把这些依赖带入 theorem/obligation 的自由变量闭包。Lean lowering 以当前词法作用域渲染值实参，保留其 MathIR 表达式和绑定；编译器不会新造维度、索引、非零条件或 Lean 假设。抽象类型类需求分析也递归检查依赖参数中的表达式，但只记录从原表达式得到的结构需求，不把需求升级为命题前提。

现有线性代数运算扩展到 Mathlib 索引矩阵 `Matrix m n α`：加减、乘法、转置、单位矩阵、迹、行列式的类型分支识别索引类型；乘法严格要求左列索引类型和右行索引类型相同，结果为 `Matrix leftRows rightCols α`。本批同时打通数乘，以及矩阵乘 `Fin n → α` 函数向量，结果为 `Fin m → α`。后者直接对应 Mathlib `Matrix.mulVec` 的函数表示。

MathIR 原生 `Vector[d, α]` 和 Lean 核心 `Vector α n` 仍是不同的数据表示，编译器不会将两者互相伪装。本批的依赖类型示例覆盖核心 `Vector α n` 的类型/Kernel 路径；矩阵向量积使用 Mathlib 标准 `Fin n → α` 表示。

## 仍有限制

- `TypeApplication` 是开放式、受常量名语法限制的表示，不包含一份 Mathlib 常量签名/宇宙层级数据库。任意构造器真实存在与否、值参数种类/个数是否符合该构造器签名，最终由锁定 Lean statement elaboration 检查；它不是 Lean 类型反射器，也不自动推断缺失参数。
- 通用 indexed Matrix 的迹、行列式和单位矩阵已有类型/lowering 分支，但本批真实 Kernel 集成直接覆盖的是乘法、加法、转置、数乘及 `mulVec`；不把未在本批运行的迹/行列式实例记为实测通过。
- 未增加矩阵逆、秩、线性相关/独立、张成、基、维数、核/像、特征值或一般线性方程组对象体系。核心 `Vector α n` 也尚未接入本批的通用加法、范数和矩阵乘法运算。
- 本批没有补齐抽象类型类的通用实例推断、全部数域歧义的 Lean lowering、几何、概率、拓扑、完整微积分/级数和一般递推对象。Mathlib 中这些对象仍可在来源明确、表达契约已支持时通过 `TypeApplication` 表达类型；相应 MathIR 运算、来源证据和证明路线必须逐项实现与验证，不能据此宣称整个领域已支持。
- SwiftUI/Native 源码未改。客户端数据契约新增的可选 MathType 字段为 `termArguments`、`argumentOrder`；消费依赖 MathType 时需保留字段并避免把 Lean 核心 Vector 与 MathIR 固定维 Vector 混为一类。本批未做 Swift JSON 解码测试或 GUI 验收。

# 证明代码来源标记（2026-10-14）

## 根因与修复

V2 的 MathIR 起始结构要求 `proofTerm: null`；proof-only 生成和 diagnostics repair 随后会写入形式证明代码。工作流事件保留了补丁来源，但逐步验证结果、压缩后的 Native API 响应及最终 MathIR/run artifact 没有逐节点来源标记。只看最终 proof term 时，调用方无法区分它是本轮生成、修复，还是 MathIR 开始时已存在。

`backend/v2/workflow.py` 现在在每次 Lean 验证后给逐步结果加 `proofTermOrigin`。来源值为：

- `missing`：该次验证时节点没有 proof term。
- `preexisting`：本次工作流开始时 MathIR 已有 proof term。它不表示该代码由用户撰写，也不表示原稿授权了该证明。
- `previously_generated`：调用方通过现有 continuation 参数提供了完全匹配的既有生成项。
- `proof_only_generation`：本轮 proof-only 阶段产生。
- `diagnostic_repair`：本轮 AI diagnostics repair 阶段产生。
- `deterministic_diagnostic_repair`：依据 Lean diagnostics 执行并重验的确定性 proof-only 清理。
- `unattributed`：验证结果含 proof term，但当前工作流没有可验证的来源记录。

`backend/v2/service.py` 将该字段透传到 `verification.routes[].steps[]`、verification history，以及最终 MathIR/run artifact 的 `proofTermOrigins` 索引。该字段只描述形式 proof code 的工作流来源，不是 SourceRef、语义对齐、用户作者身份或数学正确性的证据。数学判定、Statement/Proof Lock、路线依赖审计、Lean 与 Kernel 均未修改。

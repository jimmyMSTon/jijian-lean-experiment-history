## 本批实现

第二批补上第一批参数化类型缺少的值索引绑定，使同一数学类型机制可以表示依赖函数、有限索引族及 Mathlib 标准的维度对象。`Function` 类型新增可选 `binderId`：未设置时仍是普通箭头，设置时是 `Π` 类型，绑定声明的类型必须与 domain 一致，绑定只在 codomain 中可见。Codomain 的依赖项在函数应用时按实参捕获安全地替换；依赖绑定不会泄漏成 theorem 参数，约束与作用域检查也会拒绝越界引用。

类型相等现支持依赖绑定的 α 等价，但自由声明 ID 仍需一致。`TypeApplication` 可组合值参数，例如 `Fin n`、`Finset (Fin n)` 与 `Matrix (Fin m) (Fin n) ℝ`；Lean elaboration 仍会核验构造器、参数数量、参数类型及实际库声明。没有新增类型值白名单，也没有推断新的维度、数域或数学前提。

矩阵运算的现有类型视图已接通标准 `Matrix` 类型应用。维度可由带来源的 `Fin` 值索引表达，矩阵加法、乘法、转置、迹、行列式及矩阵乘向量继续经过静态形状检查和 Lean elaboration。向量加法、减法、数乘、点积、平方范数现在也接受 Mathlib 常用的 `Fin n → α` 表示；点积和平方范数当前只定义为实值 Euclidean 运算。数乘可表示标量域与载体不同的抽象向量：对 `V` 使用 `Module K V` 时必须有原文支持的类证据；若原文说“向量空间”，Mathlib 还要求显式表达 `AddCommMonoid V`，不会从一个类 binder 自动假设另一个类。

MathIR Pydantic schema、`MathIRV2.schema.json`、`StructureOnlyMathIRV2.schema.json` 以及结构化 prompt 已同步 `binderId` 与作用域规则。未修改 Swift 客户端、API response shape、DeepSeek Provider、Mathlib 检索策略、Statement Lock、Repair 或 Kernel 实现。

## 当前边界

依赖函数 binder 的声明式 `constraints` 目前不接受；如果条件是命题组成部分，必须明确出现在 MathIR 命题/上下文中，不能由类型转换自动补齐。Mathlib `TypeApplication` 的完整构造器签名与实例约束最终由 Lean elaboration 核验，静态层不会假装具备全库反射。Fin-indexed 向量点积与平方范数当前限制在 `ℝ`；抽象 `Module K V` 已在 `Fin n → V` 向量加法/数乘路径做初步接入，但一般模块运算、矩阵缩放与矩阵秩/核/像/特征结构、几何、概率和分析的跨层广覆盖仍未由本批整体验收。形式命题的 Kernel 证书不证明自然语言/图像来源与 MathIR 语义等价，`semanticAlignmentKernelProven` 仍按既有契约保留。

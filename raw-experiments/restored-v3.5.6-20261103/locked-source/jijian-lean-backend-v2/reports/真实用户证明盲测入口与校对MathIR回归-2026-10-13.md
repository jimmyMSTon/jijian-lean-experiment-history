## 工程基线与修改

从统一主线 `dc76ad1f2bc0dcf645c08791aa561343875d5b68` 接续。新增 `scripts/run_user_proof_blind_case.py`，作为显式、单样本的真实用户验收入口，支持文字、图片、手写 strokes 和按顺序混合输入；使用当前真实 DeepSeek 配置及源码指纹匹配的 Lean Runtime。该脚本不属于 App 启动路径，不由普通测试执行，不安装 fixture Provider，也没有加入 live 开关、请求次数、Repair 轮数或 Token 上限。

每次执行在私有新目录中拒绝覆盖旧证据。启动后先 fsync `run-started.json`；来源哈希/assetId 写入 `source-files.jsonl`；图片识别和每条人工 correction 分别即时写入 `recognition-checkpoints.jsonl`；V2 过程事件和状态追加到 JSONL；最终机器结果与内容去敏的请求审计写入 `blind-result.json`。结果缺少 pipeline 返回值时标为 `failed` 或 `interrupted`，不会写成 Kernel 通过。reference 数据只能放在独立 `referenceFile`；清单其它部分内嵌的参考字段会被拒绝，reference 路径不能与输入图片或 manifest 重合。程序必须先落盘机器结果，再打开 reference 文件并生成单独的待人工比较证据。审计导出使用字段白名单，不写 API Key、prompt 或响应正文。

另修改 `tests/test_ai_test_architecture.py` 的执行意图检查。此前它要求每个包含 `Services()` 的脚本都调用 `install_dev_ai()`，误把明确 live 研究入口也要求替换成 fixture。现在只对两个明确列出的 live 入口分别检查 workflow/request 审计和可恢复证据；其他服务脚本仍须遵守原有 instrumented/mock 约定。没有改 Provider 选择或正式业务逻辑。

入口说明在 `docs/真实用户证明盲测验收入口.md`，命令为：

```sh
.venv/bin/python scripts/run_user_proof_blind_case.py /path/to/case.json
```

## 当前证据边界

本轮完成的是通用的本机盲测执行与留证机制，不是实际用户证明验收。协作同步记录的最新手写证明图片仍在 ChatGPT 会话侧、未交到此 Mac 的盲测目录；现有本机人工转写案例也没有独立参考文件可供严格盲对照。因此没有向模型发送相同旧题、没有把 synthetic fixture 算成视觉识别、也没有报告新的数学正确率。单独的历史 Lean/Kernel 成功只说明对应固定形式命题的证明内核结果，不证明原稿与 MathIR 语义等价。

待原始素材和独立参考文件以分离文件交接后，可用该脚本一次性保存识别文本、人工修订、sourceRefs/MathIR、固定 statement、ProofTerm、Lean diagnostics、原路线/Kernel 结果、逐请求 token 与阶段耗时，再在模型输出持久化后进行盲参考核对。Native SwiftUI、App 构建和安装路径均未改动。

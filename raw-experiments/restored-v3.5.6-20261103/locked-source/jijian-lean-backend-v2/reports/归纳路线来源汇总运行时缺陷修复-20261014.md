# 归纳路线来源汇总运行时缺陷修复（2026-10-14）

## 发现与根因

在最终来源状态字段更新后，对真实 Lean/Kernel 路线矩阵做当前主线复核时，归纳路线在 Python 汇总阶段抛出 `AttributeError: InductionCase has no attribute sourceAssessment`。该异常发生于 Lean 已执行之后、`verify_v2` 汇总路线来源状态时；它不是 Lean 证明拒绝，也不能记作归纳数学验证失败。先前编译器用例没有调用完整 `verify_v2` 汇总，因此漏掉了这条路径。

`verify.py` 汇总 route assessment 时把归纳案例纳入来源判断，但 `MathIRV2.InductionCase` 原来只有 `sourceRefs`，没有 `sourceAssessment` / `assessmentBasis`。同一结构字段因此在其他节点和归纳案例之间不一致。

## 修复

- `backend/v2/models.py`：给 `InductionCase` 增加 `sourceAssessment` 与 `assessmentBasis`，默认 `not_assessed`；`supported` 必须带显式依据，与其他来源承载节点一致。
- `backend/v2/structure.py`：明确要求结构化输出保留归纳案例自身的来源评估。
- `contracts/MathIRV2.schema.json`、`contracts/StructureOnlyMathIRV2.schema.json`：从当前 Pydantic 模型重新导出。
- `tests/v2/test_v2_kernel.py`：验证归纳 case 来源状态进入 route source summary，并拒绝缺依据的 `supported` 声明。

未更改归纳表达式、ProofLock、依赖审计、Statement Lock、Lean 或 Kernel 规则。

- 非 live、非 Lean-local 全回归：`513 passed, 26 deselected`；1 条既有 Starlette/AnyIO 弃用 warning。`compileall` 与 `git diff --check` 通过。
- 已认证 Lean 4.34 Runtime `8ed0581c17efdbc6c9f64ccb66dad3768b4feb21ce25f501aab79b229e7443bd` 的真实路线矩阵：`1 passed, 141.38s`。同一矩阵断言普通正确命题 Kernel 通过、错误 `1=2` proof 未建立、两路线分别 incomplete/passed、有限有理数和 Kernel 通过。归纳样例固定命题 Kernel 通过，但原路线保持 incomplete，因为记录的归纳步骤 proof 实际可由 `simp` 独立成立、没有使用其声明的 IH；这是依赖使用审计的正确拒绝，不能作为完整归纳路线通过。

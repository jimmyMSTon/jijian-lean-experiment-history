# 极简 Lean｜原稿自然语言推理的独立来源认证

日期：2026-10-18（北京时间）。起始已安装 / 稳定源码版本：`d44be986c6dc6aee661ec5d2126471e8e812366c`。

## 本轮原始问题

旧 `reasoning_fidelity.py` 对所有原稿步骤一律写死 `originalInferenceVerified=false`，即使用户清楚写了可数学核对的“等式两边同加”“移项”“代入”“等式链”，系统也不能给正确原稿正向认证。反过来，用户写“因为 0=0，所以 n+1>n”这类无关理由时，即使 AI 构造了另一个 Lean 正确证明，也绝不能把那份 AI 证明说成学生原稿正确。

## 已实现：严格区别 Lean 证明和原作者推理

- 新增 `backend/v2/source_inference.py`。它独立读取源输入中的数学文本片段，通过一套**确定性原始公式解析与数学变换**检查：源中实际方程与 MathIR 是否对应、原稿中明示的推理动作是否与前一步及当前一步一致、依赖前提是否真实参与计算。不是由 DeepSeek 声称 sourceAssessment=supported 来决定，也不查生成的 proofTerm 是否出现依赖变量。
- 当前已能正向识别并独立核对的明确推理包括：多项式恒等式、由已给等式进行符号变换、等式两边实施相同操作、精确等式代入、等式传递。运算词与结果必须吻合（说“加 3”不能用“乘 3”的 MathIR 或“加 4”的形式表达冒充），类型域与文本声明必须匹配，源中的“因为 P”不能被 AI 换成实际代码所用的另一个 Q。
- 审计会核对**原始证明范围中的显式等式及因果短语是否得到来源标注**，避免模型只保留正确步骤却漏掉同一原稿中另一个错误方程。中文来源代码点的上标展开保留原始字符范围，防止公式漂移到其他句子。
- 只有确认 `sourceEvidenceHash`、锁定 Lean statement、statementHash、真实独立 Kernel route/step 证书相互匹配，且所有给定路线声明的源推理步骤均得到精确数学规则证据时，该完整 route 才能获得 `originalProofVerified=true` / `sourceProofVerified=true`；证据保存明确的 sourceRef、源文字哈希、所用规则、依赖 IDs 和独立核验状态。旧历史无认证不能凭布尔值自动升级。
- 原有形式 Kernel 状态完整独立保留。后端在 run / checkpoint / history / 事件 / 报告契约中持久化来源认证。SwiftUI 的单步显示同时关联正确 route、node、rule 与独立审计结果；即使整体证明尚未确认，已经独立认证的局部步骤也如实显示，不再被整体状态压成“全部待核对”。
- **未新增**模型门禁、网络/调用次数限制、测试发布 Gate、题型白名单、自动审核流、数学假设或对用户问题的修改。

## 真实 DeepSeek、MathIR、Lean 4 + 独立 Kernel 证据

下述数据均来自独立工作树的真实现有 provider / Kernel 链路，**不是 fixture AI 冒充成功**，运行后的 source rule 审计还在当前修复代码中独立回放：

1. 原稿：“因为 a=b，在等式两边同时加 1，得到 a+1=b+1。” → DeepSeek 2 请求，输入 12,089 / 输出 4,387 tokens；Kernel `originalRouteKernelPassed=true`，独立推理规则 `explicit_equality_congruence`，`originalProofVerified=true`。见 `reports/source-rule-live-congruence-20261018.json`。
2. 新措辞：“设 x、y 为实数，已知 x=y。证明过程：由 x=y，在等式两边同时加 3，得到 x+3=y+3。” → DeepSeek 2 请求，输入 12,066 / 输出 5,580 tokens；完整 Kernel 形式证明 `true`，来源推理认证 `true`。见 `reports/source-rule-live-new-wording-20261018.json`。
3. 负例：“因为 0=0，所以 n+1>n。” → DeepSeek 5 请求，输入 138,293 / 输出 23,288 tokens；完整形式证明并未获得 Kernel 证书，`originalProofVerified=false`。这说明实际工作流未误报，但**不能替代**“Kernel 另证结论成功、来源无关理由失败”的强负例。此类强负例由现有保存的证书形状及模型误用反例在确定性审计回归里覆盖。见 `reports/source-rule-live-irrelevant-premise-20261018.json`。
4. 此前用户三题的真实代数 `a+b=5, ab=6 → a²+b²=13`，5 步原稿全部经独立数学规则回放认证；来源是在 `tests/v2/fixtures/recorded_real_algebra_source_rule.json` 中保留的真实 DeepSeek 结构、真实 Kernel 证书（从历史隔离 DB 提取）。来源内容非手造 proof。

## 实现范围和数学可信边界

这**不是任意一般自然语言数学证明的通用语义完备判定器**。当前正向来源认证仅能覆盖独立解析出来的具体等式与有限的明确代数推理规则，尤其非算术逻辑推理、一般归纳/量词推理、复杂几何、概率、手写原图语义对应等尚无同等的独立来源证书。不会因为 Kernel 命题为真就跳过来源核对，也不会将“未认证”称为“数学错误”。系统不阻止其他证明形式的原有 DeepSeek/Lean 正常验证；只是对无法取得独立来源推理证据的原稿不宣称这部分已验证。

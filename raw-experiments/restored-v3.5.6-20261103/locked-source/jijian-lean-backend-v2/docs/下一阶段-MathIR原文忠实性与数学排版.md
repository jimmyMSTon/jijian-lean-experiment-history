# 极简 Lean｜下一阶段工程方向（2026-10-09）

本文件是**已确认产品目标的执行研究建议**，不含新业务规则、数量阈值、样本门槛或发布 Gate。数学结构与证明忠实性若需改变正式数据契约或拒绝条件，先报告差异给用户确认，再进入产品实现。

## 当前已经有的能力与剩余风险

- `MathIR` 已保存：`source/raw/normalized/blocks`、`sourceRefs`、变量域、定义、假设、目标、证明步骤、依赖/作用域/歧义和自然数归纳结构。
- `backend/mathir.py` 检查 sourceRef 范围、作用域、依赖 ID、归纳变量角色等，是必要的**结构正确性**。
- `backend/statement.py` 固定 canonical expression、binder map、theorem 和 statement hash；proof-only 模型不能改命题。
- 当前**缺少对人类原文与 MathIR 语义的通用一致性证明**：源码检查无法得知首次识别是否漏 `sinθ`、前提是否被 AI 初次误译、来源坐标是否真实贴合原图片。
- `canonical_plan` 中还含中文“平方/非负”特判，这不是可以泛化所有学科的来源审计。
- 数学表达树明确支持标量算术、量词、比较、求和、正余弦、多项式 `eval` 等；积分、极限、矩阵、向量、集合、几何等仍缺同等完备的结构表示。
- `sourceRefs` 已有，但照片来源主要定位到段落/步骤级；逐字符、逐公式区域的红绿覆盖并无足够源坐标证据。

## 适合 Codex 的下一项（现有范围内）

**建议先做只读原文忠实性审计，证明当前哪些 MathIR 字段真正有原稿依据，再讨论增量协议实现。**

1. 审计 `backend/mathir.py`、`models.py`、`statement.py`、`lean/compiler.py` 中来源绑定/作用域/外部假设引用，说明可能放过或误拒的场景。不得把 keyword 规则当作通用形式语义检查。
2. 以现有录制的用户原证明为证据，对照原始文字、MathIR 假设、类型、量词、证明步骤、局部假设和 `sourceRefs`。含不确定解释的只报告，不编造正确结论。
3. 列出现有 MathIR AST 表示不了的数学对象/证明结构及当前具体现象，**不擅自把支持域设为白名单**。
4. 对原图定位只记录真实 `bbox`/来源证据，解释哪里只能标步骤、哪里可以准确标公式，不得插值为虚假像素定位。
5. 给出不改用户命题的**通用来源审计方案**，和需要用户确认才能实施的任何数据契约/状态变更分别列明。
6. 不修改生产 DeepSeek、Kernel、MathIR 验证行为，不新增模型路由、API Gate、调用次数限制、自动人工审核或题型限制。

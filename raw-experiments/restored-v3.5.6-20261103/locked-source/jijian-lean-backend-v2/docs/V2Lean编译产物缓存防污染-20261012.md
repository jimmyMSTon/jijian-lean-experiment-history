# V2 Lean Runtime 防旧编译产物污染｜2026-10-12

独立研发分支 codex/v2-native-proof-evidence。没有修改 DeepSeek、MathIR、Lean/Kernel 判定，也没有改变用户验证额度或错误修复规则。

## 已确认风险

原 prepare_lean_runtime.py 在第一次准备版本化缓存时，把旧 Runtime 作为 APFS 克隆种子复制进 staging，然后覆盖当前 Lean 源码执行 lake build。原来的缓存就绪条件只核对 Lean 源码 fingerprint 与 Wire/Export/Audit .olean 文件存在性，不校验编译产物内容。过去曾发生三字段与四字段 jj_export 协议版本不一致的问题。

## 修复内容

- 新 cache layout 指纹命名空间，保留旧 Runtime 目录和旧开发 App 不变。
- 在独立 staging 中只移除本项目 Jijian/Wire、Jijian/Export、Jijian/Audit 的旧本地 .olean/.ilean/trace/hash，强制 Lake 编译当前源码；不操作 Mathlib packages 或用户数据库。
- 编译完成后写入三个项目 .olean 的 SHA-256 到版本标记；下次复用缓存时重新计算二进制 hash，不再凭文件存在就放行。缓存被修改则明确拒绝复用并保留目录以排查，不静默复原或删除。
- 不引入 Codex、Lean skill 或新模型到最终用户运行架构。

- tests/test_prepare_lean_runtime.py 增加陈旧种子被清理重编和编译产物被篡改后不被复用的负面回归，配合图片/手写历史来源合约共 6 项本地测试通过。
- 真正 Lean 4.34.0 Lake build Jijian 6 job 全部成功，输出源指纹 121db4b260cd82a7e0721248b495e13c7f2c8cb40dee840234eb3bf6e00f904a，版本化运行时源目录和 compiledModuleSha256 与实际 .olean 一致，_is_prepared 返回 True。没有启动 DeepSeek 请求。

# 极简 Lean V2：原稿来源状态与独立 Kernel 结论分层呈现

## 确定性 UI 缺陷

当前 V2 后端已有严格来源核对字段 originalMeaning、unresolvedAmbiguityIds、sourceAlignment、transcriptStatus。这些字段不改变 Lean/Kernel 的数学证明有效性，但能够表示原图转录是否尚未核对、用户人工修订、原稿语义与结构化解释是否冲突、或是否存在未解决的识别歧义。

原 SwiftUI 的 ProofRecord.status 与 NativeResult 只读取 MathIR 顶层 ambiguities。当真实来源的 transcriptStatus=not_assessed 或 sourceAlignment=contradicted 且 MathIR.ambiguities=[] 时，会直接显示普通的「形式化原证明路线已通过 Kernel」。页面虽有通用免责声明，但没有清楚告知这一份**具体原稿来源**尚未核对，容易把已验证的形式化命题误认为已验证原图和手写证明。

## 此次修复

- ProofRecord 新增只读来源状态 headline/explanation，严格消费后端 originalMeaning，首先读取 V2 run 顶层字段，兼容旧存档的 verification 内同名字段；历史没有新增字段时只在已存 transcriptStatus 或 MathIR ambiguity 明确要求时采用安全回退，不猜测用户原稿是否已核对。
- 明确展示 5 种来源状态：unresolved_ambiguities、transcription_not_assessed、source_assessment_contradicted、corrected_transcription、semantic_alignment_not_assessed。未发现任何上述来源警告时，不凭空增加警告。
- 原正式 Kernel Verified 仍依据不可变的原路线 kernel/依赖证据计算，**不更改数学证明结论，也不以原图来源状态替代 Kernel 结果**；仅在用户可见状态旁增加对应的来源限制，并在成功/失败页显示实际后端已知的信息。
- 更新 NativeFailureSummary 的独立来源核对项，避免后台已有转录警告但列表「原文歧义 0 项」的自相矛盾。
- 无改动 MathIR、DeepSeek、视觉 Provider、Lean/Kernel、Repair、Runtime、Git 历史、持久化 schema。

# V2 原文与 Lean 命题对照｜Native 证据字段修复（2026-10-12）

工程起点：Codex 已收敛的 3ef6089；本提交仅修复证据透传和界面表示，不涉及 Proof/Repair 数学判断。

## 已确认的缺陷

backend/v2/verify.py 的步骤核验在内存中包含每个 obligation 的 expectedType。
backend/v2/service.py 调用 compact_verification 存档时漏掉 expectedType。
macos/Native/BackendClient.swift 因而只能从 sourceRefs 获取用户原文，并把同一原文同时填入 ProofRow.original 和 math。
结果界面的“数学陈述”无法供用户比较实际被 Lean 验证的类型/数学命题，存在证明源文漂移而界面看不出来的风险。

## 本次改动

- V2 compact step 增加 expectedType，保留原有 Lean expectedType 文本，不由 UI 重算或让 LLM 自报。
- ProofRecord.formalType(for:) 通过 routeId/nodeId 在所保存的 V2 verification 中返回确切目标，不改变原 ProofRecord.verified 与 V1 旧历史语义。
- NativeStepDetail 和 NativeSourceMapping 在已有原稿和步骤视图中单独展示“Lean 核验目标（形式化）”，并说明步骤未通过时该目标尚无 Kernel 证书。
- 对旧 V2 存档中缺少 expectedType 的情况说明记录未保存该目标，而不是将原文冒充为 Lean 类型。
- sourceRefs / status / dependsOn / failureClass / Kernel 判定和相关 MathIR 全部未改；正式存档 App 与旧 main 未更新。

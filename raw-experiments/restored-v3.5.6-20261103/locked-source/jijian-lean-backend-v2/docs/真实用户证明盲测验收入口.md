# 真实用户证明盲测验收入口

`scripts/run_user_proof_blind_case.py` 是独立研究入口，不属于 App 运行时，也不会被普通测试自动执行。显式运行时使用 `Settings` 当前配置的 DeepSeek Provider 和已准备的源码匹配 Lean Runtime；它不设置 `LIVE_AI_TESTS`、调用次数、Repair 轮数或 Token 限额。

## 样本包

每个样本用一个 JSON manifest 描述。路径相对 manifest 目录解析；reference 文件单独保存，不放进 input 对象。

```json
{
  "format": "jijian-lean-blind-case-v1",
  "caseId": "student-proof-01",
  "input": {
    "kind": "image",
    "file": "original-proof.jpg",
    "mediaType": "image/jpeg",
    "corrections": [
      {
        "blockId": "b0",
        "start": 12,
        "end": 13,
        "expectedText": "l",
        "replacement": "1"
      }
    ]
  },
  "referenceFile": "independent-reference.json"
}
```

`input.kind` 支持 `text`、`image`、`strokes`、`mixed`。`mixed.parts` 按原稿顺序保存文字、图片或手写数据；每个图片/手写 part 可带逐条用户确认的 correction patches。patch 使用 recognition block ID 与 Unicode code point 半开区间，按数组顺序应用。manifest 输入中若出现 `reference`、`independentReference`、`referenceAnswer`、`expectedAnswer`、`expectedVerdict` 或 `goldAnswer` 字段会被拒绝；reference path 也不能指向 manifest 或其中一张输入图片。参考文件仍只会在 blind result 持久化后读取。

独立参考 JSON 由审核者另行编写，可包含原证明整体判断、逐步判断、第一处错误、未完成步骤和识别歧义。格式由研究者解释，不作为模型 prompt schema。

## 运行与产物

```sh
.venv/bin/python scripts/run_user_proof_blind_case.py /path/to/case.json
```

默认证据目录为 `~/Library/Application Support/JijianLean/proof-acceptance/<caseId>/<时间>-<随机ID>/`；也可传 `--output-root`。Provider 配置优先使用显式 `JJ_ENV_FILE`；若未指定且 `~/Library/Application Support/JijianLean/server.env` 存在，则复用 Mac App 的同一服务端配置，否则回退到仓库 `.env`。配置值不会写入验收证据或终端输出。脚本为每次运行新建私有目录并拒绝覆盖既有证据。`run-started.json` 在调用服务前保存输入清单快照和运行身份；`source-files.jsonl` 逐项落盘来源 SHA/assetId；`recognition-checkpoints.jsonl` 在视觉识别返回后、以及每条人工 correction 后立即保存 raw/normalized text、识别 ID 和修订链。`runtime-data/` 保存 SQLite、原图资产和 V2 checkpoints；`workflow-events.jsonl` 记录阶段事件；`workflow-status.jsonl` 追加运行状态；`blind-result.json` 保存最终 source structure、MathIR、固定 statement hash、proof/Lean/Kernel 结果、每步诊断、依赖证据、完整请求审计和 token/耗时汇总。Provider 审计的 started/finished 事件均同步落盘；报告按 `request_id` 合并两种事件，started 后缺少 finished 的请求标成未闭合尝试，不会被误计为零请求。`providerUsage` 分别给出实际 Provider 尝试、模拟传输、审计未闭合项和 Token 汇总。

关键盲测次序由入口保证：先完成识别、用户修订和 V2 pipeline，原子写入并 fsync `blind-result.json`；之后才读取 `referenceFile`，单独产生 `reference-comparison.json`。对照文件保存两份证据的 SHA 并标为 `pending_human_review`，不自动把某个 reference 字符串等同于程序真值。provider 请求审计只导出明确字段，不包含 API Key、原始 prompt 或响应正文。可捕获的取消/异常会通过 finally 保存 incomplete/failed 结果；若进程被强制终止到无法运行 finally，已同步写入的阶段证据和 request audit 仍可供人工恢复审阅，但此时不会自动生成 `blind-result.json`。无论哪种中断，都不会提前读取 reference。

样本交付时，应把原图/文件、manifest、人工 correction patches 和独立 reference 分开管理。运行后先冻结 `blind-result.json`，再由 ChatGPT/审核者检查模型输入证据与独立参考；所有失败应区分识别/MathIR、Lean 未建立、依赖不符、Kernel 未通过和供应商/系统错误。fixture 与模拟 Provider 结果不能代替该入口的真实调用证据。

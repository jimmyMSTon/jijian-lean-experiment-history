# V2 补丁说明

## 本轮修改的真实基础

V1 已经存在 MathIR 1.0、`FormalTypes` / `FormalProofs` 分离、不可变原始记录、逐步骤检查、完整证明组合与独立内核复核、一次修复接口和简易源码关键词搜索。本补丁在这些代码上扩展，不另写一套互不兼容的后端。

## AI 与识别

`backend/providers/deepseek.py` 使用 DeepSeek 官方兼容 Chat Completions 的 HTTP 协议。文本/图片放在用户消息，图片使用 `image_url` 数据 URL，结构化输出使用 `response_format={"type":"json_object"}` 并在本地做 Schema 校验。保留供应商模型、响应编号、系统指纹与 token 用量；不保存/返回供应商的私有推理链。

`FlashVision` 专门转录原图，然后结构化模块在已有来源记录上构建 MathIR。两个步骤可以分别排错；转录阶段不解题、不“纠正”原数学、不编造坐标或置信度。用户更正后的文本在结构化阶段优先，不能再被旧原图覆盖。

图片使用原版方向修正。手写笔画保存原始坐标、时间与压力，渲染 PNG 后发给 Flash；这不等于 Flash 原生理解时间序列笔画，也没有宣称个性化字迹模型已训练。渲染用的边距/线宽是代码细节，不是用户必须采用的书写规格。

PDF 使用 `pypdfium2` 在本机逐页渲染，复用原 `/api/recognition/pdf/{id_}` 轮询结构。每个轮询推进页面处理，保存已完成页和识别证据，完成后的重复轮询不会重新调用模型。页数不裁剪，空白页仍在证据中。PDFium 并发访问在渲染层串行化，以符合其线程安全要求；没有限制用户可创建的任务数量。

旧式 `/internal/ocr/pdf*` 是原 Mathpix 网关专有协议，新版 Mac 后端不再调用它，旧调用收到明确的兼容提示。新 PDF API 的前端入口未改变。

## 当前 Mathlib 的检索

默认路径为 `LEAN_PROJECT_DIR/.lake/packages/mathlib/Mathlib`；保留原 `MATHLIB_SOURCE_DIR` 配置。源码目录中检索名字、模块路径和跨行声明头，维护按文件变化更新的索引；不设固定返回条数。

Flash 先输出检索词或候选声明名，源码检索返回候选；随后运行当前 Lean 的 `#check @名称`。只有真实命令成功并返回类型报告，才标记 `found=true` / `status=lean_checked`。源码检索是轻量词法索引，可能漏掉宏生成、复杂别名/命名空间等情况，不能自称完整环境索引；直接声明查询仍可交给 Lean。

返回的数据分别保留 `sourceMatches` 与 `declarations`，记录工具链/Mathlib manifest 指纹、源文件指纹、查询诊断。源码中的声明头不冒充 Lean 完整类型报告。统一 `import Mathlib` 沿用原环境，未宣称已计算最小 import 集。

本轮没有加互联网检索、向量数据库或额外嵌入 API。

## 命题固定与修复

初始形式化翻译类型/命题后，通过 `probe_statement` 检查可否在当前 Lean 中建立对应表达式，诊断传给证明生成器。这是类型检查，不能验证自然语言语义是否等价，不能把它当作新的“语义已通过”证书。

`Compiler.statement_fingerprint()` 绑定 MathIR、形式化类型、局部上下文、结论、作用域和依赖。原哈希与新指纹共同用于修复记录。AI 仍只返回 `sourceId/proof/translationNotes`；不能通过响应字段重写 theorem statement。

流水线复用原 verification，然后对已有 Lean 证明诊断发起同模型修复。每轮保存版本和诊断来源；修复的数学输入与命题不变。模型返回无法忠实翻译的空片段、声明自身出错、没有可修 proof 的诊断、环境失败等如实返回未完成，不用“试了很多次”推导原题错误。

没有配置式轮数上限、费用阈值、重复结果阈值或其他模型兜底。不收敛但持续生成同样候选时，任务仍可通过既有取消接口终止；该行为和可能持续的模型调用在接续说明中明确披露。网络调用本身不自动重试，原来的重启中断策略不变。

即使每一步的形式化证明通过，原来的完整证明组合和独立审计仍须产生真实证据才设置 `kernelVerified=true`。本补丁没有“只看退出码成功”“只看模型说通过”的快捷路径。

## 前端兼容

MathIR schema 仍为 `1.0`。原有请求字段与结果字段保留，流水线结果增补修复记录编号/状态。客户端连接层增加 librarySearch/libraryLookup，UI 无需强行展示它们。

`/api/formalize/repair` 保留单次修复语义；完整自动修复由 `/api/pipeline` 或 jobs 执行。任务进度可显示“检索/修复中”，不新增确认页、Gate、额度或题型筛选。

## 本轮没有交付的东西

本补丁不是新 `.app`，不包含 Stitch 文件、密钥、Mathlib 缓存或 Lean 二进制，没有构建/签名 macOS 安装包。真实手写质量、真实 DeepSeek 延迟/费用、真实 Lean 编译成功率没有在无凭据环境虚报。具体检查范围看本轮验证报告。

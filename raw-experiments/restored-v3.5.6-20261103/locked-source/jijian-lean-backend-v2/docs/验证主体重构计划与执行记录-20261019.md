## 整体重构的工程设计与实施次序（不是新增产品 Gate）

1. **数学真值与用户推理的裁决解耦**。数学义务由原稿路线的声明、作用域与表达式构成，经 Lean Kernel 检查；数学上的蕴含有效性不等于 Lean 证明语法中每个前提变量都必须出现。生成证明项的 binder-use 审计保留为 provenance 观察证据，但不阻断已经有真实独立 Kernel 证书、完整路线依赖、所有步骤可证的 **形式证明成功**。未被实际使用的作者理由绝不自动认证为来源忠实。
2. **来源优先的义务图**。先从用户原文位置与 MathIR 中忠实抽取来源步骤、原文片段、显式理由、条件和结论；为每步保存可复核的 obligation、原始引用哈希、数学变量/量词作用域及缺失证据。保留所有源步骤，分开返回未识别、来源不一致、逻辑不成立和证明代码错误；不能用模型的自评 supported 冒充独立证明。
3. **只修真的数学证明义务**。Proof-only / Repair 关注 Lean 实际未证明的数学义务、范围和 Kernel 诊断；如果形式 Kernel 已通过，只剩依赖项在生成代码里未被语法调用，不再引发昂贵的模型反复 Repair。单题工作流复用未变化义务的已验证 Kernel 证书；改动任一 proofTerm / expectedType / 来源对应则重新核验，且最终完整形式路线仍独立 Kernel 验证。
4. **数学表示与类型支持**。处理文本裸字面量与 MathIR 原生数域运算的合法对应问题，例如实数上下文中的整数常数、自然数专属互素运算中的非负整数常数；保留数学前提与原始来源，记录规范化过程而不暗改数域。结构化失败保留真实模型输出与确定性诊断，不归咎于学生数学。
5. **一体化联调及交付**。用历史真实 DeepSeek/Lean 证据重放强正负案例，用真实安装版数学题完成新鲜联调，完成 Python、Swift、签名和正式 App 全量构建。分别报告稳定形式能力、原稿真实忠实性、人工不可确认部分、请求与性能。保护并行工程工作树，安全合并当前 Git main，保留旧版可恢复归档。

## 不改变的边界

不自行增加模型调用次数门槛、题型白名单、自动收费或权限、UI 审批步骤、全局离线 Gate、额外数学前提、发布硬条件。数学无证明时只能记录未证实，不能宣布原命题为假。重构可调整验证主体内部函数与报告证据，但保持历史数据的可读性与 Mac App 人类数学交互方向不变。

# 极简 Lean｜旧任务与新文稿身份、取消和迟到结果隔离

日期：2026-10-15。Native 主线基线：e91ac8b（包含 Codex 的真实图片/PDF 迟到竞态和超时探针修复），此分支只新增不重叠的 Native 任务生命周期机制。

## 具体缺陷与后果

1. NativeStore.observe(id) 将任务的失败结果提交到全局 fail(error)，即使用户已 newProof/editDraft 到另一个文稿。旧 MathIR 结构失败会覆盖新文稿的界面并显示系统错误。
2. 完成任务与阶段性 checkpoint 主要通过原文字符串和 JSON 源键判断是否仍属于当前文稿。如果用户建立新证明、却又输入一模一样的文本，则旧 Kernel 结果可以错误归属新文稿。
3. cancel() 的 POST await 之后无条件 observer?.cancel()、activeJob=nil 和 UserDefaults.removeObject(native.activeJob)。如果旧任务先于取消请求结束、新的付费任务取得编号，再收到旧取消响应，新任务将失去追踪，用户无法可靠取消或读取结果。
4. 旧取消/中断若恰好遇到新图片导入，其终端 UI 回调可能覆盖新识别页。异步保存识别校对再切块的失败，也缺少文稿版本校验。
5. 这些问题是原生任务归属漏洞，不是用户数学推理错误；修复不得引入任何模型次数限制、全局离线 Gate 或跳过独立 Kernel 的分支。

## 通用修复

- 每次任务 ID 被接受时固定 submittedRevision，同时保存提交原稿文本与 JSON 来源键；App 从持久化任务恢复时归属于恢复的当前文稿版本。currentInput 文本相等不代表两个用户文稿相同。
- UI 验证任务的 SSE 进度/MathIR 显示、最终 verified result、error、取消/中断 checkpoint 均检查 submittedRevision 是否仍然等于 documentRevision。过时任务只可成为 previousRecord 或说明性 notice，不得自动成为新文稿的 Kernel/数学判定。
- verify() 不会因新文稿的内容字面相同就复用旧 activeJob；仍保持单一可追踪的任务槽，用户应先等旧任务结束或取消后再提交新稿。
- cancel() 在 HTTP await 返回后必须再次检查正在观察的 activeJob ID；只释放它自己拥有的 ID。旧取消请求不得取消/清空后来接受的新任务及其 UserDefaults。异步读取 checkpoint 后再次核对 documentRevision，不覆盖随后导入的原稿页面。
- selectRecognitionBlock(index) 完成待保存校对后同时核对 documentRevision 和 blocks.indices，防止旧 PATCH 错误覆盖新工作，拒绝负数/不存在的索引。
- 不新增网络请求重试，不发起第二个模型任务，也不改变后端 Provider、MathIR 类型器或 Lean/Kernel。

## 独立测试证据

在独立临时 UserDefaults HOME、localhost 延迟 HTTP、真实 Swift NativeStore/SwiftUI 源码和非 UI_FIXTURE 的测试 harness：

- A：旧图片上传成功但新文稿已经创建，不能继续产生旧视觉请求。
- B：旧上传 HTTP500 返回时，新图片仍在上传，旧回调不得关闭新 busy 状态或显示旧错误。
- C：旧视觉识别响应迟到，不能覆盖新文稿。
- D：多图片上传第一个资产后新文稿创建，不应继续上传后续旧图片、也不应启动废弃的 mixed 识别。
- E：旧 V2 MathIR 校验失败返回，新文稿不变为系统失败。
- F：新文稿与旧文稿文本完全相同也必须以 documentRevision 区分，旧任务不能复用或污染它。
- G：旧任务获得模拟 Kernel 成功结果，但新文稿文字相同，仍不得把模拟的旧成功结果归属新稿；这一项只是 Native 结果绑定测试，非真实数学 Kernel 成功证据。
- H：旧任务取消响应晚于新图片开始上传，新图片的 recognition/import 页面不应被旧取消回调覆盖。
- I：取消旧任务时，若接受任务槽已经交给另一任务，旧取消不得清除新的 activeJob / UserDefaults。
- A-I 通过：9 组，0 DeepSeek、0 Mathlib、0 Lean、0 用户 App 数据访问；模拟成功/失败任务仅用于测试 Native 状态。
- 此外对 Codex 既有 tests/run_native_job_lifecycle.py 的真实 Swift HTTP 测试再次执行，结果以正式运行输出为准。

# 极简 Lean V2｜历史坏记录隔离与旧缓存污染修复（2026-10-13）

## 起因
持续开发主线 e8baf69 的 NativeStore.loadHistory 原本一次 try 包裹整个 V1+V2 加载。只要某个旧 V1 verification 缺少 formalization 关联，或者某条 V2 run 缺少 MathIR，任何 artifact 请求 404 都会中断整次 loadHistory，让其他完好的证明也不可见。此前成功载入的历史缓存在新一次载入失败时也未清空，容易误认为旧历史仍是最新查询。

## 修复
- 分别获取 V1 与 V2 历史索引，每个 artifact 关联读取拥有自己的 do/catch；坏记录不会遮蔽其他可用记录。
- 显示不可读取的具体条数。没有隐瞒错误，也不删除、自动迁移或推测缺失原稿。
- V2 依然必须存在 mathIRId 与非空 MathIR；不把不可读取的数据补成虚构证明。
- 在开始刷新历史时先清空旧列表；如果后端重新加载失败，保持原证明编辑状态，但不展示可能来自旧后台的列表缓存。
- 可用记录继续按原 ISO timestamp 排序；所有旧 Kernel/依赖真值与成功语义不变。
- 不修改 MathIR、DeepSeek、Lean Runner/Kernel、数据 schema 或模型调用行为。

## 实际回归
- tests/run_native_history_integrity.py 编译真实 NativeStore.swift 与其它 Native Swift 源码，连接一个本地 HTTP 测试服务，不启用 UI_FIXTURE、不使用用户数据。
- 测试服务返回四条历史索引（V1 两条/V2 两条）；每种类型故意缺少一条关联 artifact。
- 真实 URLSession 逐项读取的结果保留 2 条完好记录、正确标注 2 条关联缺失，按真实时间顺序排列，并打开一个 Kernel-verified V2 的原文。
- 人为使后端历史 API 下一次返回服务不可用；NativeStore 显示加载失败、列表空，不污染当前已打开证明。
- 本次本地测试 0 DeepSeek 请求、0 Lean 请求，不当作模型数学能力的新测试。
- 修复仅针对单条 artifact 失效；如果整个历史索引服务不可用，仍显示整体错误，不误报历史为空或自动向模型重试。

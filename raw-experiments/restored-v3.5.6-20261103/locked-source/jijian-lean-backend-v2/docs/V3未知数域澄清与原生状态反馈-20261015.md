# 极简 Lean Native｜V3 未明确值域的安全反馈

## 根因

2026-10-15 Codex 在 MathIR V3 为源稿缺失数域的场景加入 TypeVar、typeAssessment、clarificationRequired。后端会拒绝 V2_TYPE_DOMAIN_UNRESOLVED 并保存未验证 MathIR 草稿，不会猜测为 Real 或锁定 Lean statement。然而原 Mac NativeSystemError 只显示一条通用 MathIR 结构失败诊断；使用者无法直观看出应该人工核对或确认数学值域。

## 改动

- NativeV2StructureFailureEvidence 中增加严格受后端 validationCode=V2_TYPE_DOMAIN_UNRESOLVED、clarificationRequired.kind=mathematical_value_domain 双重约束的来源澄清说明。
- 即使 HTTP 失败后的 draft GET 尚未完成，读取已保存的错误 details 也能明确显示「需要确认数学值域」；不显示模型列出的候选域为已获授权，更不偷偷填 Real/Rat，也不将缺少数域等同于学生数学步骤错误。
- 匹配到验证失败草稿后，额外指出不会创建锁定命题/提交 Lean，并确认用户原稿未修改。
- 其它结构失败（作用域、binder、类型不匹配）原有定位机制不变；「返回原稿」保留，「立即重复相同输入」仍不鼓励。没有新增模型/Repair 调用 Gate。

## 测试与限制

- 独立 Swift NativeV2StructureFailureEvidence 单测 PASS：验证 V3 缺数域错误、错 kind、错 validationCode、draft 尚未返回、未验证草稿与通用错误分流。
- 对完整 Native Swift 源文件进行真实 SwiftUI typecheck：PASS。
- 本改动仅前端文本呈现，没有 DeepSeek 请求、没有 Lean 或 Kernel 运行；它不能替用户自行确定原数学对象的合法值域。
- 用户手写数列首轮 MathIR 错误仍保留，不能因 V3 TypeVar 出现就改称原稿 Kernel 已证实。实际完整图片盲测仍需已确认的数学值域与有效结构。

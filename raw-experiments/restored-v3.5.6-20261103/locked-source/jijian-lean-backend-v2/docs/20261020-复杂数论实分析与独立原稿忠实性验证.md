## 1. 原始工程目的和本轮功能边界

用户只提交自己的数学题和原证明；DeepSeek 负责数学结构翻译，Lean/Mathlib 独立 Kernel 确认形式数学义务，每个原稿理由是否与原文、依赖和数学规则对应，由独立来源审计决定。形式正确不等于学生原证明正确。对不能独立确认的理由保持“未认证”，不是“已证明数学错误”。

- 用户 V2 封存版本 `316ad4f` 及全量 Git 与旧签名 App 完整归档，未修改。
- 新主体是唯一正式开发主线，不并行维护 V2 验证器；不增加全球离线 Gate、次数/费用阈值、数学题型阻断名单、强制人工步骤、隐藏数学前提。

## 2. 复杂数论：全链通过，来源扩展认证

- 真实软件新运行：`reports/official-core-next-numtheory-live-20261020.json`；总耗时 **235.984 秒**；真实 DeepSeek **1 请求**（Proof-only；结构化来自来源保真的已有缓存），input **5,741**、output **26,825** tokens。没有人工 MathIR 或 Lean proof。
- 全部 **9/9** 原稿声明的形式主张通过独立 Lean/Mathlib，完整固定命题的 Kernel `checked=true`、`statementMatched=true`、`additionalAxioms=[]`。旧版本已因声明/作用域/类型无法进入 Lean，现在实际完整证明通过。
- 同一次运行的旧独立来源判定因仅支持等式语法而返回 0/9、`sourceProofVerified=false`。
- 新增源码 `backend/v2/source_predicate_rules.py`，在真实保存的 DeepSeek MathIR 和独立 Kernel 证书上进行**不调用模型**的独立来源语义回放：核对源文所写的整除、互素、连续整数的偶性、模余数条件、穷尽分类，和来源支持的 P 定义；每步实际 Typed Lean Obligation、依赖列表、sourceRefs、MathIR/source hash 与证书完整绑定。结果 **9/9 原稿步骤来源正向认证**。
- 每个规则按数学数字/变量参数解析，非固定 n/3/6 题目硬编码，不能把 AI 自评 supported 当证书。错误互素因子、错误余数、遗漏或多余分类、错写 P 定义、错误整除结论、无关“因为 7=7”、偷偷删除原稿数学句子及旧 Kernel 证书跨 MathIR/dep 复用都由负例拒绝。这些负例中的“模拟重绑定哈希”是安全单元测试，**不是重新执行了负例的真实 Lean**。
- Source predicate 的正向认证只覆盖确实能从原始文字独立解析的语法及已证的本地义务，不能宣传成任意数学语言都已认证。今后源码文档不得将 9/9 回放伪称为当前已安装 App 的新鲜 Provider run，除非新打包版本实际重新跑过并得到相同结果。

# 极简 Lean V2｜任务取消后恢复已保存证据（2026-10-12）

开发分支：codex/v2-native-proof-evidence。起点包含 Codex 780e5f9 的 Proof/Repair 收敛、图片手写恢复与 Native 提示。本变更不影响原证明成功判定、声明依赖、Statement Lock、Kernel、模型策略和费用规则。

## 已查实的用户链路断点
Codex 的新鲜开发版 DeepSeek E2E 测试使用源码 780e5f9，独立数据库位于极简lean-review/latest-v2-real-e2e-20261012。7 次真实 DeepSeek 响应、4 次 Lean verification，运行 357.53 秒后任务取消，无最终 mathir_v2_run；但数学工作流已持久化 9 个 mathir_v2_checkpoint，含用户原稿、MathIR 以及已得到的分步 diagnostics/Kernel 证据。此前 Native UI 在 status=cancelled/interrupted 时只返回工作台，已保存步骤无法查看。

## 本轮实做
- backend/api.py 新增只读 GET /api/v2/jobs/{id}/checkpoint。首先检验 job 存在，再沿该 job 自身的 mathir_v2_checkpoint_saved 事件找到最新 checkpoint。只有当前任务本来就持有该 checkpoint id 才会读取，防止跨任务错配。不返回重型历史、proof wire 或所有 retrieval records。
- API 明确 partial=true、status=incomplete，固定将顶层 originalRouteKernelPassed/fixedStatementKernelPassed 标为 false，原始步骤级证据仍原样返回，绝不把局部 Kernel 通过冒充最终原路线成功。
- NativeStore.swift 的取消和中断观察分支优先读取本地已保存的 V2 阶段性结果，在原稿未变时打开失败/未完成步骤视图；若原稿已变化，不覆盖用户正在编辑的内容。不存在 checkpoint 时保留旧“取消并返回工作台”行为。
- BackendClient.swift 的 ProofRecord.verified 明确不将 partial 当成功，中文状态写明“仅展示已保存的阶段性核验结果”。
- 不创建新任务，不重识别，不重新调用 DeepSeek，不启动 Lean，没有新增全局离线开关或产品请求阈值。

## 实测证据
- API fixture 合同测试（含跨任务读取拒绝和不存在任务）通过，3 passed / 1 lean_local deselected。
- Native Swift ProofRecord 的 partial 与通过步骤并存时，实际模型可执行测试通过；Native Swift 全部文件 typecheck 通过。
- 真正取消的开发 E2E 数据库闭合副本：GET checkpoint HTTP 200，partial=true，jobStatus=cancelled，原路线 Kernel 顶层=false，1 条 route、1 个 step，0 Provider 请求。sanitized 证据：/[LOCAL_USER]/Documents/ChatGPT/极简lean-review/latest-v2-recovery-contract-20261012/contract_result.json。
- 没有对 Codex 正在使用的 SQLite 进行写入或重跑付费模型。
- 此功能尚未人工点击 GUI 做端到端验收；Native 逻辑由 Swift 运行测试与全量类型检查覆盖，不应冒称真实用户窗口点击已通过。
- 旧存档 App 不是当前开发目标，不覆盖旧运行文件；此提交只在隔离 Git 分支上。

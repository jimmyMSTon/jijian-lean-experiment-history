# 局部见证作用域与表达式类型标注：真实失败驱动修复

日期：2026-10-18（北京时间）。开发基线：`3e32abe`。本轮依据同日三题真实测试中第二题出现的 `MATHIR_V2_INVALID / V2_EXTERNAL_ASSUMPTION_SCOPE` 修复通用数学结构，不改题目或原作者文字。

## 机制与实际改动

1. 模型可能把局部见证的条件 `n=2k` 错置于仅能保存锁定定理全局前提的 `assumptions`，同时在原稿证明路线内部已完整保留同一个 `local_assumption` 节点。新增 `materialize_route_scoped_assumption_views`：只有在作用域、数学表达式、来源区间、sourceAssessment 都与已存在的局部原稿节点一致时，才消除 **同一源条件的重复存放**；绝不把局部条件提升为 theorem assumption，不增节点、不改用户原文、保留完整原条目在 normalization audit。对于缺失/矛盾/无来源/跨路线不能唯一映射的输入，保留原有确定性拒绝结果。若存在原先直接引用错误 assumption ID 的 `dependsOn`，只映射到同一路线里已经存在的相同局部节点。
2. TypeChecker 的 `typing` RouteNode 从只能表示“变量 : 类型”扩展为完整 `ascribe(expression, targetType)` 的 **显式类型正确性检查**，例如在局部声明 `k : ℤ` 下，`(k² : ℤ)` 也是合法来源类型说明。它只接受静态可核对的类型判断，不成为新 theorem premise、不生成数学 claim，也不替代 Lean 证明。
3. DeepSeek 结构化说明更加明确，局部见证与 `P(k)` 必须留在局部 route/scope，不能抄入全局 `assumptions`。不改变模型、调用路径、ProofLock、Lean Kernel、修复次数或产品流程。

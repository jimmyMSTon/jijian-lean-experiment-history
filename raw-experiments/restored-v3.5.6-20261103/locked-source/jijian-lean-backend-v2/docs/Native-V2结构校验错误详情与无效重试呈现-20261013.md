# 极简 Lean V2｜真实用户样本暴露的结构失败诊断丢失与无效重试按钮

## 真实故障证据

用户 2026-10-13 上传数列题印刷图片和手写归纳法证明，ChatGPT 使用手工逐行转写稿（**不是**原图视觉识别）对真实 DeepSeek Flash 进行首次 blind MathIR 结构化，仅一次请求；该真实结构调用返回 MATHIR_V2_INVALID，details.validationCode=V2_BINDER_UNKNOWN，details.draftId 指向隔离 Store 中已保存的 mathir_v2_draft，Lean 没有执行。实际 DeepSeek 3517 input、44146 output，其中 reasoning 32377、HTTP 176065.949 ms；重试 index=0，0 Mathlib/Repair。完整后台证据路径 /[LOCAL_USER]/Documents/ChatGPT/极简lean-review/user-samples/proof-20261013-001/。

原 Swift BackendClient.request 解析非 2xx 后只保留 error.code、error.message 且丢掉 error.details；后台 job 最终错误的 details 同样在 NativeStore.observe 又被丢弃。NativeSystemError 对 MATHIR_V2_INVALID 这种确定性结构失败始终展示“重新验证”，导致用户容易对相同原稿再次发出昂贵请求，而 MathIR/Lean 根因完全没改。

## 本次 Native 修复

- ClientFailure 增加可选 details 字段，默认空，确保所有历史初始化调用仍然兼容；HTTP 422 的 details 原样保存（无额外请求）。
- NativeStore.fail 保留具体 errorDetails，后台 job 失败路径同样传递 error.details；newProof 清空历史错误标记。未修改原稿或 Kernel 结果判断。
- NativeSystemError 对确定性 MATHIR_V2_INVALID 展示“当前没有 Lean 验证结论”和实际 validationCode。因为不修改相同 MathIR 再请求没有意义，隐藏立即重复提交同样原稿的快捷按钮，保留“返回原稿”修改后正常发起业务请求；没有添加全局模型 Gate、调用限制或禁止用户在工作台重新验证。
- 其它网络/Runtime 系统错误仍可正常重试，不把之前的结构化详情串到下一次错误。

## 真实客户端验证

- tests/run_native_job_lifecycle.py 连接实际 Swift NativeStore 和 ephemeral URLSession 到延迟本地 HTTP 模拟服务；模拟网络任务确认期间用户修改原稿，并发提交被去重，1 次提交+1 次取消。
- mock 另返回 HTTP 422 MATHIR_V2_INVALID，带 validationCode、draftId。实际 Swift BackendClient 捕获 ClientFailure.details，NativeStore.fail 正确保存错误代码和结构化证据，标为 systemError，保留新原稿，且不会把结构校验误判成数学错题。不同 BACKEND_START_ERROR 不携带旧 details 且保留一般重试入口。
- 真实编译全部 Native SwiftUI 依赖和测试入口，测试 PASS；0 DeepSeek/Lean 请求；正常清理本地 HTTP mock。代码格式和 git diff --check 通过。

## 重要边界

这次修复的是错误反馈契约，不能令本次不支持一般数列的 MathIR 自动变成可证明的形式命题。真正数学泛化（Nat→Real 索引序列/函数、induction binder 等）交给 Codex 在独立数学后端分支设计通用 AST/Compiler/TypeChecker，不用样本硬编码或换命题求通过。原始图片还没有进入 Mac，不能称视觉 LLM/用户整条证明 Kernel 通过。

## 2. 数学扩建缺口不是某道题的漏洞

### 必须从通用数学对象解决的 P0
1. **声明/数学载体缺省**：数列、函数、分式等对象的值域或代数结构未确定时，能表示“尚未确定且缺少何种约束”；不擅自用 Real。对于不能证明或不能唯一定型的对象，提供结构化 pending/clarification 结果，而不是非法定理。
2. **绑定与词法作用域**：唯一 binder、α-重命名正确性、遮蔽/逃逸/捕获防御及来源位置之间双向关联；任何自动 α-规范化必须证明不改变变量绑定含义，不能仅为通过测试改 ID。
3. **合法条件与证明依赖**：除法非零、矩阵可逆、索引非负/截断、对数定义域、根的范围、二阶递推两个基例、有限维维度等；系统不可隐式授权这些假设。
4. **来源语义锁定**：原始图片、修订、块文本、MathIR 和 Lean lock 逐项审计；严禁把模型重写后的证明当学生原路线。
5. **失败归因合同**：识别未确定、结构非法、无法编译、无 proof、依赖断裂、Kernel 不通过、Runtime/Provider 故障和具有反例的命题分别归类并进入 UI，不能混为“数学错误”。

### 更广覆盖依然缺乏的对象类别（应定义明确版本范围）
- 几何关系、平面与解析几何、圆锥曲线及图像假设的证据关联；
- 线性映射、秩、逆、行列式条件、特征值/特征向量、线性相关与基；
- 完整多项式因式分解、代数方程、定义域/参数讨论；
- 更系统的函数极限、连续、导数、积分及其必要条件；
- 计数/样本空间、事件、有限概率、条件概率；
- 强归纳、递推、反证、分类讨论以及量词/假设的复合推理。

数学无法“所有东西一次扩完”。需正式确定目标版本范围：**DSE/高中基础 + 常见竞赛证明/必要大学预备知识**为优先级核心；超范围必须清晰判定 unsupported，而不是模型编造近似命题。

## 3. 真正的系统一致性验收（目前尚未完成）

以下是跨层**不变量**，每个都应建立版本化、可重放的检查而不只是计数式 pytest：

- `原图 SHA→assetId→recognitionId→corrected revision→SourceBlock/SourceRef→MathIR ID→statement hash→ProofLock→独立 Kernel 证书→历史 UI` 能逐段追溯，无旧图片、旧文本、旧路由悄悄混入；重启/取消/旧任务收尾时仍成立。
- `ExprOp↔Pydantic Shape↔JSON Schema↔ARITY/变长例外↔TypeChecker↔Normalization↔Lean lowering↔模型 Prompt` 全操作/全类型一致，并覆盖非法参数、错误维度/值域和跨域组合，不是只测 `x=x`。
- `原证明 node、dependsOn、sourceRefs、kernel fixedStatement、route result、diagnostics` 一一对应，不把补写的 AI 正确证明替换学生原稿，不允许无关步骤掩盖断裂依赖。
- 同一个原稿的识别更正、变量 α 改名、合法等价排版在声明条件不变时应保持数学目标含义；错下标、错量词、漏前提、逆不等式、不合法域转换必须改变或拒绝结果，不能变成“格式变化”。
- `job lifecycle + event SSE + checkpoint + cancel + network disconnect + reopen history + app relaunch` 以及 Provider 故障、过时 Runtime、同名图片和多页 PDF 的异常路径验证。不能靠离线单点测试替代实际 App 完整过程。
- 实际测试需要 **v2 raw image new input / expected source transcription / valid type/assumption outcome / kernel verdict / original proofreading evidence** 跨层对照。人类语言和图片到 MathIR 的语义一致性不可能由 Lean Kernel 自动证明，应以独立校对和人工参考归档控制，明确其证明边界。

## 4. 预见的系统级故障类型

1. 模型输出 Schema 合法但数学语义错：量词次序、下标、领域缩窄、歧义来源引用错行。
2. 同一 binder 在多个 scope 复用，捕获自由变量；错误自动归一化可能把假命题改真。
3. 模型猜测类型/前提，或使用自然数减法截断，使递推条件暗中改变。
4. ProofTerm 已证明另外一条路线而非原稿依赖，Kernel 真但用户原证明假。
5. 缺分母非零/矩阵可逆等前提，Lean 错误被显示成学生数学错。
6. 长证明复杂度导致 Provider reasoning token/裁剪复核请求与 Mathlib/Repair 历史放大，真正 latency 无用户可见进度。
7. 来源与修订错位、跨 PDF 页面混用、撤销后旧异步结果覆盖新输入。
8. SSE 重连/取消/任务接受时序导致重复模型请求、残留子进程和孤儿 job。
9. App 打包和源码/Runtime 指纹不匹配，旧后端、旧 schema、旧历史与新 Swift UI 合约不一致。
10. 旧证明历史字段缺失、数据污染、资产丢失或不一致时被错误归为“已经验证”。
11. 大量初等运算扩建导致 prompt/schema 输出 token 暴涨，不等于真实模型可控。
12. 缺乏在正式范围内对**陌生正确/错误/不完整**证明的分领域代表性测评，存在过拟合。

## 5. 改进执行顺序与停止规则

**立即暂停**针对某一用户长证明的重复新鲜视觉/DeepSeek/Repair 全链付费实验，直到 P0 基础数学/作用域/来源锁与跨层契约通过；已保存的真实失败作为只读回归输入。并非在 App 正常业务里重新引入全局离线 Gate，也不删掉用户正常使用 Flash 的路径。

1. **功能清单封版**：确定第一版需支持的对象、证明方式、UI/图片输入，清楚标注 supported / partial / unsupported。不要承诺数学全领域一次做尽。
2. **Contract-first 集中整改**：类型/上下文/作用域/语义来源/proof route/错误分类的共同规范，消除生成、编译和 UI 之间的漂移。严格保持原命题，遇无法合法定型的输入输出结构化未支持状态。
3. **持续执行无需付费的单元/类型/Property 测试**：每次修改都跑相应契约，不可以等“所有东西写完”再测，否则无法确定修正是否引入回归。
4. **完成阶段性无付费全链预演**：保存真实 provider 输出回放、真实 local Lean 和独立 Kernel、UI HTTP/SSE 及签名 App 测试；从原数据到 UI 全流程，正反样本/错误输入都要能稳定报对失败层。
5. **上述证据充分后才做少量新鲜真实图片/DeepSeek 端到端验收**；记录成本、Token、耗时、每层证据，不再像目前用户长样本那样在结构底座未收敛前连续付费尝试。

第一版准备发布的判据：明确范围内关键对象/运算全链契约覆盖，所有 P0 错判成功/歪曲原文的缺陷关闭，真实 Kernel 证书与原步骤依赖关联准确，签名 App 具有输入-校对-编辑-历史闭环，提供稳定异常恢复及用户可辨认的 unsupported 状态；长样本成功一例不是整个产品完成的充分条件。

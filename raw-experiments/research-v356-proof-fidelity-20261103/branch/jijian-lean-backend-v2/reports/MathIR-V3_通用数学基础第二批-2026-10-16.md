## 本批实现

本批为表达层增加通用 `mathlib_const` 表达式和 `MathlibConstantReference`，以安全的限定 Lean 常量名、结构化 MathType 和必需的 `sourceRefs` 引用 Mathlib 对象或运算。它与现有 `apply` 组合，不需要为每一个新数学领域增加专用 ExprOp。常量名只允许标识符；引用类型不被当作证明或前提，锁定命题仍由真实 Lean/Mathlib elaboration 校验。

该表达已接入 MathIR/Structure-only JSON Schema、确定性类型检查、类型变量和依赖符号收集、MathType 值参数排序、替换、来源规范化、结构提示和 Lean lowering。Mathlib 常量签名里的 TypeApplication 只在该签名作用域内允许由 Mathlib/Lean 确认；它们不会因此变成全局来源声明。普通 MathIR 中的裸 TypeApplication 仍要求存在来源支持的声明，保留原有约束。

值索引类型沿用第一批 `TypeApplication` 的 `typeArguments`、`termArguments` 与 `argumentOrder`；本批贯通了这些类型在通用 Mathlib 常量签名里的使用。声明依赖图包含值索引内的符号，使用来源中已有的 `n` 时会先闭合它，再导出 `Fin n`、`Finset (Fin n)`、`Vector α n` 或带 `Fin` 维度的矩阵。没有增加隐藏变量或 theorem assumption。

结构化提示要求优先依据检索中 Lean 检查过的声明名和签名；类型内容只是模型结构化声明，Lean 再核对常量和类型。后端新增契约字段为 `Expr.mathlibConstant = { name, type, sourceRefs }`，已在以下导出契约更新：

- `contracts/MathIRV2.schema.json`
- `contracts/StructureOnlyMathIRV2.schema.json`

Native/AppKit/SwiftUI 文件没有修改，未做客户端解码适配或 App 构建。本字段对客户端是可选表达节点；若 Native 直接渲染 MathIR，需要将它读作已来源映射的数学对象引用，不要把 `name` 或 `type` 当成 Kernel 证明。

## 仍未完成

- `MathlibConstantReference.type` 当前复用 `Function` 表达，支持参数固定后具有非依赖 codomain 的函数签名；MathIR 尚无一般 dependent-Pi 表达式，不能完整描述显式输入值会改变输出类型的函数（如依赖前一项函数参数构造后续类型）。此类对象应保留为未形式化，不用错误的普通 Function 类型近似。
- `mathlib_const` 提供开放的数学对象入口，但没有让所有 Mathlib 定理自动可用。名称、声明类型和最终证明仍须能从当前 Mathlib 与 Lean 环境检查；复杂隐式参数、依赖函数和结构级条件仍需要后续通用表示能力。
- 本批未建立多项式因式分解、线性映射/秩/谱、平面几何、积分/概率等领域的完整操作与数学定理覆盖；现有对象可与通用 Mathlib 引用组合，但本报告没有把这种可表达性等同于领域证明能力。
- 尚未运行完整的最终 39 项 Lean 专项回归、真实 DeepSeek、Native Swift 解码、Mac App 构建或安装。

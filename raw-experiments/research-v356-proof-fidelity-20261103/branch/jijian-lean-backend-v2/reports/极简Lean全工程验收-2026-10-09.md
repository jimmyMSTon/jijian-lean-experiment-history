## 2. MathIR 代码层审计

真实模块：`backend/models.py`、`backend/mathir.py`、`backend/statement.py`、`backend/lean/compiler.py`、`backend/formalization.py`、`backend/verification.py`。

**已有：** 原稿/规范化输入、source blocks 与 sourceRefs、variables/domain、definitions、assumptions、goal、proofSteps、scopes、dependsOn、ambiguities、typed expression AST、自然数归纳结构；类型校验、依赖拓扑、局部假设作用域与循环检查；固定 binder map、canonical specification、statement hash；proof-only 生成和局部 repair；逐步 Lean 验证、conditional dependencies 与完整 aggregate；独立 Kernel 证书及原文步骤映射。

**核心局限与风险：**
1. MathIR expression op 当前主要覆盖标量算术、序关系、逻辑量词、有限求和、函数调用、正弦余弦与实系数多项式 eval；尚无同级专门 AST/渲染支持以完整涵盖微积分、极限、矩阵、向量、集合论、几何等广泛数学。部分通用 apply/constant 可编码片段，不等于完整端到端支持。
2. Statement Lock 锁定的是**AI 首次解释生成的 typed MathIR**；它能阻止之后改前提/变量/命题，却不能证明 MathIR 与原文语义一致。这是面向“验证用户原证明”最关键的剩余可信边界。
3. `backend/statement.py` 的 `canonical_plan` 内仍存在识别中文“平方”“非负”的**样本特化前提校验**；不能作为通用来源归属检验；可考虑由通用 source/provenance + scope 检查取代，但未经确认不更改。
4. 对图像定位，当前 Flash 识别记录 `locationPrecision=reading_order_only`，UI/记录主要到 source block/步骤级；尚未证明可在用户原手写图像上精确逐字符/逐笔画荧光标注。
5. 自然数 induction 结构存在，但并不意味所有证明方法、抽象归纳、多分支、论文级长证明已经实测稳定。
6. 核心可信边界文档 `docs/可信边界.md` 已如实指出：Kernel 只证明数学形式项；原文忠实度仍依靠识别和结构化质量。通用反例证明模块尚未实现；未证实不能误报数学反例。

**积极做法：** `ProofRecord.verified` 不把 unresolved ambiguities、simulated 或未建立步骤显示成整体通过；`FeedbackService` 不把 Lean 未完成等同于用户数学错误。

## 4. SwiftUI 客户端与输入差距

- 精细数学 TeX 排版对复杂/不支持表达会回退原文；矩阵、积分等真实高质量展示需要专题检查。
- 原稿红绿显示以步骤/源块为主，不是已验证的图上逐字符/公式区域定位。

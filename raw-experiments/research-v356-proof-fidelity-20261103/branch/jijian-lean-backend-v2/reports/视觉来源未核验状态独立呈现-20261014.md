# 视觉来源未核验状态独立呈现（2026-10-14）

## 根因与修复

`backend/v2/verify.py` 会分别汇总模型对 MathIR 来源的判断、识别/转录状态和 Lean Kernel 结果，但对 `transcriptStatus=not_assessed` 的视觉来源，`_source_alignment_status` 原先会直接返回模型的 `supported`。`_original_meaning_fields` 也可能把这类输入标为 `model_interpretation`。这会让结果字段看起来比实际来源证据更确定。

现在转录未评估与语义对齐未评估分别保留为 `transcription_not_assessed` / `semantic_alignment_not_assessed`；模型评估标为矛盾时使用 `source_assessment_contradicted`，不再混称为歧义，也不声称这是独立数学反例；校对文本、歧义和模型解释分别报告为 `corrected_transcription`、`unresolved_ambiguities`、`model_interpretation`。各自的 `sourceAlignment.status` 与 `transcriptionStatus`、`modelAssessment` 一并保留，Kernel 和逐路线结论没有被改写。Kernel 只证明固定 Lean 命题与原路线；它不会升级图片转录或 MathIR 语义等价状态。

改动文件：

- `backend/v2/verify.py`：保留未评估转录状态，并计算来源含义总状态。
- `backend/v2/service.py`：在 compact history 的逐步结果中保留 `sourceAssessment` 和 `assessmentBasis`。
- `tests/v2/test_source_coverage.py`：覆盖“模型标 supported + 图片转录未评估 + Kernel 状态为 true”时的字段分离、corrected transcript、矛盾 assessment 定位到对应 step 并保留进 compact history。

## 客户端契约

客户端可分别处理 `originalMeaning` 的 `transcription_not_assessed`、`semantic_alignment_not_assessed`、`source_assessment_contradicted`、`corrected_transcription`、`unresolved_ambiguities`、`model_interpretation`，并结合 `sourceAlignment.status`、`transcriptionStatus` 与 `modelAssessment` 展示来源证据。`kernelVerified` 继续只表示原路线在锁定 Lean 命题上的 Kernel 结果；来源状态需要单独呈现。本轮未改 SwiftUI / Native 文件。

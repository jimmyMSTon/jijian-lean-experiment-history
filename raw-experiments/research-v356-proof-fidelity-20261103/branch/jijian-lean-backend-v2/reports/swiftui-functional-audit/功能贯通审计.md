# SwiftUI 交互与数据贯通审计

审计范围：当前 macOS 原生 App 的现有页面与可见交互。没有增加页面、产品规则或正式产品状态；没有改动 Provider、MathIR、Mathlib Retriever、Lean Runner、Repair 或 Kernel。

## 当前运行和构建

- 正式入口是 `macos/Native/NativeApp.swift` 中的 SwiftUI `App`，根视图为 `NativeRoot`。正式 App 不载入 WebView；Stitch 导出只作为视觉参考。
- 正式 App 使用 `NativeStore` 和 `BackendClient` 连接本机后端；本次启动时 UI 显示“本机服务已启动”，`/health` 返回 `running`。Health 仅证明服务进程存活，不代表 AI 或 Lean 验证成功。
- 正式 App 已重新构建为 arm64 macOS `.app`，代码签名在磁盘上通过验证。构建脚本复用了未修改的已打包后端。
- 正式 App 使用系统默认标题栏；实际运行的辅助功能树包含系统 Close、Minimize、Full Screen 按钮。标题栏可拖动，窗口保留标准缩放行为，内容从标题栏下方开始排布，没有绘制自定义交通灯。
- 本机 Lean 示例经 `scripts/check_examples.py` 实际运行：`localVerified=true`、`statementMatched=true`、无额外公理。该项是 Lean/Kernel 本地验证，不是 AI 调用。
- 本地回归：`pytest -q --ignore=tests/test_live.py` 为 **305 passed, 1 skipped**。此前本轮完整运行中过的两项 live DeepSeek 测试因服务凭据被拒而失败；没有重跑，也没有将其计为本地 UI 或 Lean 回归失败。
- TypeScript 编译器 `tsc` 在本机 PATH 不可用；本次 UI 改动为 Swift，未修改 TypeScript 客户端。

## 控件审计中确认的非独立功能

- “项目结构树”是当前导航标签，点击后回到工作区；项目没有单独的结构树页面或独立结构树数据视图。本次没有新增该产品页面。
- 草稿编辑器的 H1/H2、粗体/斜体、定理/引理/公式按钮只对当前 NSTextView 应用视觉属性；底层证明数据仍保存为纯文本，样式不会作为结构化文档元数据持久化。这些按钮没有连接到独立格式化文档模型。
- 设置中没有独立历史产品页；历史以现有列表/Sheet 呈现，按既有范围保留。
- Mathlib 搜索结果区展示源码候选，不代表它已经进入证明或被 Lean 检查。Lean 检查仍以正式验证流程返回为准。

## 本轮修正

- 文件读取与不支持类型现在统一进入导入错误状态，保留“重新选择”操作；拖放异常不再误标为系统/服务异常。
- 相机导入错误保持导入/识别分类，不再被外层 catch 覆盖成系统错误。
- 历史读取失败不再伪装成“无历史记录”。
- 现有 Mathlib 搜索输入统一构造 URL query 参数并发起本地源码检索；增加 SwiftUI 候选结果呈现，明确标出源码位置和候选证据，不宣称已通过 Lean。
- 正式 App 的搜索回车提示改为可点击的提交按钮；搜索时显示本地 loading，首轮 Mathlib 索引完成后结果会显示在形式化细节页。
- 正式窗口改回 macOS 系统标题栏与原生交通灯按钮，页面不覆盖标题栏区域。
- fixture 预览的后端动作仅在 `UI_FIXTURE` 编译目标中被短路；正式 App 无该标记，保留真实后端连接。

- 正式 App 已重新打开核对。系统窗口的 Close、Minimize、Full Screen accessibility 元素均存在；搜索页截图显示原生标题栏。新构建的签名检查通过。

- DeepSeek 配置由 `~/Library/Application Support/JijianLean/server.env` 提供，当前实际加载到 V2 模型 `deepseek-flash` 和 `https://api.deepseek.com`；密钥值没有写入本报告。实际 API 调用收到成功响应，因此当前配置没有认证失败。此前两项 live pytest 的原始完整错误输出未保存在可核验报告中，无法追溯它们各自的 HTTP 状态；代码检查发现 `tests/test_live.py` 直接用 `Settings.from_env()`，默认读项目 `.env`，而正式 App 读用户目录的 `server.env`。本次 smoke 显式使用 App 的配置文件完成验证，不需要用户重新填写密钥。

- 在有效 proof smoke 前，我先用只有命题、没有用户证明步骤的文本做了一次真实链路探测。系统正确保留 `missing_proof`、`kernelVerified=false`，没有把 AI 自动补解当作用户原证明；该次有 3 次真实请求（MathIR、Mathlib 计划、proof generation），没有 repair。记录见 `reports/swiftui-final-text-smoke.json`。这不是成功验证，也没有重试。

## 已修复的确定性数据契约缺口

V2 verifier 已分别输出固定命题 Kernel、完整路线 Kernel、逐步来源区间及 `semanticAlignmentKernelProven=false`，但没有稳定输出客户端已使用的 `originalMeaning`、`unresolvedAmbiguityIds`。这让客户端缺少直接字段区分“当前锁定的形式命题/路线已通过 Kernel”与“用户原稿的识别或来源含义仍未确认”。

现由 V2 验证结果确定性派生并贯穿保存：

- `originalMeaning=unresolved_ambiguities`：存在未解决 ambiguity，原文字稿状态为 ambiguous，或来源评估为 ambiguous / uncovered / contradicted。
- 否则 `originalMeaning=model_interpretation`：表示当前模型形式化解释；它仍不表示 Kernel 证明了原文与 MathIR 的语义等价。
- `unresolvedAmbiguityIds` 保留尚未解决且具有 ID 的歧义项，按原顺序去重。

字段现在存在于 V2 verifier 结果、compact/native verification、持久化 run 和 Lean verification 事件。Kernel、路线完成条件、`kernelVerified` 及 API `status` 算法没有改变。旧记录没有被回写或伪造新字段。

# 极简 Lean｜Native V3 数学上下文与证明路线功能接入

日期：2026-10-16。开发起点：`1ca04e2`。本文件只记录已实现能力和证据，不定义新产品 Gate、上线限制或验收门槛。

## 发现的真实功能断层

NativeWorkspaceInspector 仍消费历史 MathIR 1.0 的 `variables[].domain`、`assumptions[].text`，而当前 MathIR V2/V3 改为 `declarations[].type`、`assumptions[].expression`、`scopes`，以及 `TypeVar`、`TypeApplication`、`termArguments`、`argumentOrder`、`declaredStructures`。因此新数学系统虽在后端生成有效结构，工作台实际显示可能缺少变量、参数化类型与前提。

此外 `NativeVerifyingDocument` 没被验证页使用，且原实现仍只读旧 `goal.text/proofSteps`。真实 SSE 已经可以加载 `jobMathIR`，页面却只显示原始输入。步骤详情使用完整 `routeId/nodeId`，而后端 V2 `dependsOn` 是 route-local node ID，导致“已引用前序步骤”不能可靠匹配当前卡片。

## 已实施的一整块功能

- 新增纯只读 `NativeMathIRContext`：对 Typed MathIR 使用 goal scope/父 scope、declarations、assumptions、route nodes，不用旧版变量字段替代；历史 V1 仍维持既有变量/已知条件显示。
- 支持类型展示：ℕ/ℤ/ℚ/ℝ/ℂ、函数、集合、有限集合、多项式、固定维向量/矩阵、`TypeVar` 未决/抽象载体、`TypeApplication` 的类型和值实参（按 `argumentOrder`），包括 `Fin n`、`Finset (Fin n)`、`Vector ℝ n`、`Matrix (Fin m) (Fin n) ℝ`。不可理解或缺失参数不会臆造类型。
- 显示明确来源支持的抽象载体 TypeClass 及单独的结构需求；运算需求明确不是自动添加的数学前提。保留各数学对象的来源评估、类型评估及原稿片段。
- 用户可在工作台右栏、验证中的结构化数学预览、结果页面的数学对象/前提折叠区、步骤详情查看相同证据。缺少真实来源区间时显示 MathIR 解释及独立提示，绝不冒充原始原稿。
- V2 `dependsOn` 仅对现有同一路线真实 node ID 补齐路由前缀，保留其他 ID 不变，使源步骤的依赖展示匹配当前保存的 row identity。
- 异常历史中重复来源块 ID、越界、空区间、缺失/循环 scope 不生成可靠原稿位置或猜测全局前提；Unicode scalar 半开区间校验与已有来源语义约定一致。
- 没有修改输入 MathIR、后端、DeepSeek、数学命题、ProofLock、Kernel 或 Repair 行为，不重识别用户原图。

## 实测与证据范围

- 原生 `tests/native_v3_math_context.swift` 与真实 `BackendClient.swift` 的 Swift 可执行检查通过：依赖类型、带源类型类、用户数学前提、来源真实性、坏来源、作用域隔离、旧 V1 兼容及 route-local 依赖对应。

- 之后是否已从 main 构建/安装、签名，依据本轮实际构建回执单独报告。

## 尚未替代的工作

本轮接通的是 V3 现有结构在 Mac 中的实际用户可见路径；它并不新增任何 MathIR 数学运算、Mathlib 定理或自动证明能力。几何、概率、完整分析等领域的引擎扩建仍由数学核心工程继续承担；原稿与 MathIR 语义一致性不可能由 UI 或 Kernel 单独证实。真实用户试用可按用户指令在主体功能建成后集中进行。

# 通用函数、条件值与闭合引理合同

本次是现有 MathIR 2.0 的向前扩展，不修改 HTTP 路由、DeepSeek 配置、客户端或独立 Kernel。表达式仍是数据，Mathlib 名称仍须由当前 Lean elaboration 校验。

## 匿名函数

```json
{"op":"lambda","binderId":"x","args":[{"op":"add","args":[{"op":"symbol","symbolId":"x"},{"op":"symbol","symbolId":"a"}]}]}
```

`x` 必须对应有明确类型的变量声明。该声明放在专用词法子 scope；`a` 来自外层来源声明。lambda 的一个参数是函数体，不能放 Lean 源码。函数体可以返回数值、函数、命题或带值索引的对象。类型检查按期望函数类型检查 domain/codomain，并对依赖 codomain 代入实参。函数 binder 的声明式 constraints 不会隐式变成函数前提；应将条件显式表达为命题或参数。

该节点接通词法规范化、符号依赖收集、代入、编译、Schema 和结构化提示。常量引用仍使用 `mathlib_const` 与嵌套 `apply`，例如 `Finset.sum S (fun n => n+1)`、`Continuous (fun x => x^2+a)`、`ProbabilityTheory.variance (fun x => a*f x) mu`。域、实例和可积性条件由原稿明确给出；库函数的总定义不等于可以无条件使用其所有定理。

## 显式结构转换

```json
{"op":"coerce","targetType":{"kind":"Function","domain":{"kind":"Real"},"codomain":{"kind":"Real"}},"args":[{"op":"symbol","symbolId":"f"}]}
```

当来源中的 `f` 是 `LinearMap ℝ ℝ ℝ` 时，上述节点显式请求其函数视图。相同机制把 `Submodule ℝ ℝ` 作为 `Set ℝ` 使用，或让其他 Mathlib hom/subtype 通过已注册 coercion 进入原有函数/集合运算。静态层检查来源类型和目标类型的结构、作用域；只有真实 Lean elaboration 才能确认该 coercion 存在。它不接受转换函数源码，不会把 `ℝ → ℕ` 解释成向下取整，不增添数域或类实例。

## 条件值

```json
{"op":"ite","args":[{"op":"le","args":[{"op":"literal","literal":{"type":"Real","value":"0"}},{"op":"symbol","symbolId":"x"}]},{"op":"symbol","symbolId":"x"},{"op":"literal","literal":{"type":"Real","value":"0"}}]}
```

三个参数依次为命题、成立分支、不成立分支。两分支必须同类型。编译器显式使用 Lean 的经典命题可判定实例构造 `ite`，不向 theorem 添加条件前提。是否使用经典基础公理由 Kernel 证书保存，不隐藏公理。

## 原步骤作为完整辅助引理

RouteNode 新增可选字段：

```json
{"id":"conclusion","kind":"claim","scopeId":"root","dependsOn":["aux"],"closedDependencies":["aux"]}
```

此片段展示节点元数据，完整节点仍必须有 `expression` 和相应 `sourceRefs`。`closedDependencies` 必须是 `dependsOn` 的无重复子集，且只能引用 claim。普通依赖维持原有「步骤结论」语义；closed 依赖的类型取自该步骤实际编译出的完整 `expectedType`，包含其原有变量、局部前提和依赖绑定。

例如，局部证明为 `∀ k : Nat, k>0 → k+1>1`，导出后仍须显式提供 `k>0` 的证明。不能把局部假设视作全局真命题。辅助步骤保持独立 Kernel 义务；最终组合引用其真实已编译证明，不用任意 inhabitant 替代局部变量，也不由 AI 重证最终结论来绕过错误步骤。兄弟 scope 的分类分支可以分别导出，再在外层按用户原分类合并。

编译器同时支持在归纳的基例、步及辅助 claim 的依赖处选择完整引理类型；复杂嵌套归纳仍受现有编译器「每 route 一项结构归纳」限制。本次没有宣称任意结构归纳/任意多 recursor 已完成。

`closedDependencies` 进入 MathIR structural hash 和 route hash。改变普通/闭合依赖即使不改变总 statement，也会改变 ProofLock。Proof-only 请求和 repair 请求保存这个字段；context 中依赖另带 `dependencyMode="closed_lemma"` 或 `"conclusion"`。验证 step 响应附带 `closedDependencies`，客户端不应把前者展示为新的全局已知。

## 前后端对接

- `Expr.op` 新增 `lambda`、`ite`、`coerce`；封闭枚举的客户端需要适配。
- `RouteNode.closedDependencies` 默认空列表，旧请求沿用原语义。
- `MathIRV2.schema.json`、`StructureOnlyMathIRV2.schema.json` 已同步；结构化阶段依旧禁止模型填写 proofTerm。
- 服务端没有要求 Native 执行证明构造；应显示函数、分段值、来源与辅助引理的局部条件。
- 未增加校对审批、题型白名单、调用额度或新测试 Gate。没有修改 Native/App，实际客户端解码及显示未实测。
- Kernel 证书只证明锁定形式命题；不证明自然语言、图示和 MathIR 的语义等价。

完整可解析示例：[分类讨论及局部引理](../contracts/examples/mathir-v3-case-scopes.json)、[线性映射函数视图及核的集合视图](../contracts/examples/mathir-v3-linear-map.json)。它们是确定性合成数学输入，包含相应证明材料，供客户端合同对接；不能当作真实用户图文识别证据。

新增字段为空时，MathIR/route/ProofLock 的 canonical identity 省略 `closedDependencies`，维持旧协议的哈希兼容；非空时完整纳入锁。库函数应用返回的参数化类型仅随该值传播，不会全局注册为来源支持的类型。

## Mathlib 常量的显式类型实参

`mathlibConstant.typeArguments` 是可选的前置显式类型实参列表，按当前 Lean 声明顺序传入；`type` 描述传参后的实际类型。例如引用 `RingHom.id` 时，`typeArguments=[{"kind":"Real"}]` 生成 `RingHom.id ℝ`，其结果类型是 `RingHom ℝ ℝ`。空列表在 canonical 序列化时省略，旧引用的身份不因默认字段改变。

这使当前 Mathlib 的真实半线性构造器可被准确表达：`LinearMap` 的参数顺序是一个环同态值，再跟 domain/codomain 类型。实线性映射应使用 `TypeApplication` 的 `termArguments=[RingHom.id ℝ]`、`typeArguments=[Real,Real]`、`argumentOrder=["term","type","type"]`。不能把它近似成 `LinearMap Real Real Real`。

显式类型实参接通作用域、自由符号、捕获检测、替换、抽象载体收集及来源规范化；它们不是未核验的 Lean 源码。隐式类型/实例仍由 Lean 根据签名检查。当前没有为任意声明提供 named implicit argument 或任意交错的常量级 type/term 参数编辑器；值参数沿用 `apply`，类型构造器自身的 type/term 顺序沿用 `argumentOrder`。

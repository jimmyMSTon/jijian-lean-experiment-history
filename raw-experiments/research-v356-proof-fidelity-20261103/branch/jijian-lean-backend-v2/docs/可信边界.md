# 可信边界与当前实现范围

## 数学含义与形式证明是两个独立问题

MathIR 保存用户原文、已识别变量、原始假设、定义、步骤、作用域、依赖和歧义。结构检查发现重复节点、错误来源位置、循环依赖或局部假设外泄时，会返回“结构化没有完成”，不会称数学命题为假。

Kernel 核验的对象是生成的形式化命题和证明对象。AI 把“正数”错译成“大于一”时，Lean 无法从形式命题自身知道原文被错译。因此本包不声称 Kernel 已证明自然语言翻译正确；原文和结构化解释保留供界面对照，未设置强制人工审核流程。

原文步骤的 Lean 类型和变量上下文在 proof 生成之前保存。显式修复只更换证明片段，类型与 MathIR 的哈希保持不变。AI 在最初结构化时误读原文仍可能发生，这不是哈希检查能消除的问题。

## 逐步与完整证明

每个用户步骤有独立证明义务。某一步引用另一步时，被引用步骤是一个完整闭合命题。独立核验可以检查“假定该引用成立，这一步是否能推导”；依赖尚未成立时显示条件性状态。

所有实际步骤都建立后，编译器把步骤证明项组合成完整证明，再通过相同独立审计流程检查总目标。原始证明中有错误步骤，即使模型能够重新证明最后结论，也不会绕开未成立步骤直接汇报原证明通过。

完整自然语言“证明策略是否完全同一”的判断仍依赖翻译忠实度；没有把它伪装为形式上已解决的元定理。

## 三个隔离阶段

1. 预期命题单独展开，输出仅含表达式的数据。
2. 候选证明在另一个目录/进程展开，导出证明项和所需的安全辅助声明。
3. 审计器在第三个新环境读取数据，重放辅助声明，把候选证明项交给 Kernel 检查原预期类型。

第三阶段不运行候选 tactic、不接受候选 `.olean`，不执行表达式数据里的源码字符串。候选程序产生的普通“success”输出不能作为第三阶段审计凭证。

Lean 宏、tactic 和展开期代码仍可能执行 IO。因此候选展开阶段配有操作系统进程隔离，并且不继承 API 密钥环境。真正的操作系统隔离器、可信 Lean 二进制、Mathlib 安装和宿主系统构成运行时可信基础；不能靠一个正则过滤器替代它们。

当前数据导出器支持表达式构造器、定理、安全定义、不安全标记为 false 的 opaque 声明，以及引用可信导入中的归纳类型/递归定义。生成过程中新增的归纳类型或递归器暂没有序列化支持，会返回未完成，不伪造证明失败的数学结论。复杂数学证明涉及这些结构时，需要扩展导出实现；这属于明确的当前实现缺口，不是用户设置的产品范围限制。

## 依赖、公理与错误

审计后的公理集合保存在证据中。Lean 常见基础公理 `propext`、`Classical.choice`、`Quot.sound` 与“证明占位”区分处理。`sorryAx` 不作为已完成证明。其他额外公理显示为条件性结果。用户明确给定的数学前提则作为命题参数存在，不由 AI 私自转成新全局公理。

执行超时、进程隔离缺失、库不可用、类型展开失败、未解决目标、反例已验证是不同事实。目前没有通用反例核验端点，所以生产结果不会返回“已用反例证明原题错误”。

## 状态与数据安全

- HTTP 200：接口完成响应。
- 任务 completed：任务流程完成。
- localVerified：当前步骤在其形式化上下文中通过。
- established：当前步骤及其引用依赖已经建立。
- kernelVerified：完整组合证明通过了本次独立审计。
- originalMeaning：翻译对应关系/输入歧义说明，与 Kernel 结论分开。

错误反馈默认由程序根据真实状态生成；可选 AI 解释另存，不能覆盖结论字段。AI 建议不会自动改变用户证明或假设。

本机工作区没有实现公开多用户的访问隔离。服务连接令牌和 CORS 是部署连接设置，不是新增产品登录功能。网关公开部署涉及的 HTTPS、凭据管理、并发容量、用户级权限体系须按实际部署配置；本包不声称已经在公网运行或已通过安全审计。

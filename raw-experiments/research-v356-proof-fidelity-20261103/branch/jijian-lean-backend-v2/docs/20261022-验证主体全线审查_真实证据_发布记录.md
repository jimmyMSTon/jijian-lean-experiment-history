- AI 结构化失败、无法表示的原数学对象、缺失 Mathlib 常量、类型/作用域不符、来源语义不确定时均返回未验证而非添加前提、改变结论、编造原作者步骤或宣称来源通过。数学原文的 Unicode 来源跨度不可被模型更改。
- 单元测试中使用虚拟 provider/runner 的结果不能计为 DeepSeek 真实请求或 Lean Kernel 证书。真实 E2E 文件、Provider request ID、Token、sources SHA、独立 Kernel 证据保持可追溯。

## 二、全线可复现故障与通用修复

1. **复杂 JSON 结构化失败**：三份正式安装版及后续模型真实失败响应暴露 DeepSeek 在深层 MathIR expression.args 中遗漏数组/对象闭合符号。解析器现使用 JSON 字符串安全的容器栈与精确祖先 JSON 字段路径，仅在明确的 Declaration.value、Goal.expression、ProofRoute.nodes[].expression、Induction.predicate 已存在字段边界恢复括号；另外识别 RouteNode.scopeId 前语法上多余的括号对。完整 Schema/Pydantic 审计保持强制，且保留原始无效响应。所有修正只涉及实际 JSON 分隔符，不改数学树字段、算符/类型/值。
2. **Schema 通过仍被数学类型规则拒绝**：复用原识别源，仅将已隔离的 AI 候选和精确的字段路径/错误回传 DeepSeek 重构；新的诊断状态才允许新的翻译尝试，相同诊断重现立即停止。对于用户原文真正缺失载体的类型歧义，必须明确问用户，而不通过重复模型调用选择类型。
3. **定义集合被模型错译为谓词函数**：引入通用 set_of：α→Prop 明确构造 Set α，Lean Mathlib 对应 Set.ofPred；仅当原稿实写具名集合构造语法、匿名函数确实是 α→Prop 且元素类型严格相等时在锁定定理前转换，并保留来源 spans 和全套 normalization 审计。不改谓词或证明。包含真实连续函数/上确界的原始失效 MathIR fixture。
4. **已证前提不能帮助后续缺失步骤**：Proof-only 生成/Repair 后，如果真实 Lean 局部证书新确认了该未完成义务的显式前序依赖，允许用新 Kernel 证据再次生成缺失 ProofTerm；前提必须实际 verified/checked/statementMatched，不是模型自己声称通过。重复语法变体、无新证据和相同输入不可触发付费循环；固定命题及原稿 DAG 继续锁定。
5. **源文数学域可能被扩大而假阳性**：作者写 f:[0,1]→ℝ，但 AI 转写 f:ℝ→ℝ，这二者没有机械证明等价；新增保守独立源域守卫，在准确作者源码跨度中检测此类可证的显式不一致，令来源忠实性保持 False、暴露 sourceDomainConflicts。形式 Kernel 成功不会抬升为作者原稿通过。未覆盖的数学句法绝不因此得到推定认证。

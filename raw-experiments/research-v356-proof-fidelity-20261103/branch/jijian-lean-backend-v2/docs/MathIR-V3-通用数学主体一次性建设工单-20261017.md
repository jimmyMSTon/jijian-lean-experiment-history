## 1. 首要通用底座：MathIR 从有限 ExprOp 向开放 Mathlib 类型化数学语言演进

现有 `MathType.TypeApplication`、源支持的抽象 TypeVar、Pi/Fin-indexed 类型和 `Expr.mathlib_const` 是基础，但它们尚未形成跨领域可组合的完整表达框架。**真正将 Mathlib 标准数学对象、关系、操作与定理应用连入 MathIR 和 Lean 编译器**。

要求以实际 Mathlib 声明名和参数/返回类型为可信身份，支持复合 `apply`、部分/高阶应用、类型和值参数、显式 binder 与依赖类型、必要的类型类参数、函数复合、数值/命题混合表达、合法的显式类型转换，逐层保存来源和类型信息。Mathlib 常量名称不代表库里真的存在；必须能用实际 Lean elaboration / #check（必要时）核验。不能把未检查的任意 Lean 源码或 tactic 当成 MathIR 定义。对常用类型引入可复用的类型/结构接口而非大量专用 `if op == ...`。

扩建核心类型推断与约束：泛型 TypeVar 的 unresolved/abstract 来源区别、带作用域的 Pi 类型与 α 等价、捕获安全替换、结构类声明/实例证据、TypeApplication 的 type/termArguments 和顺序、函数的 domain/codomain、具体实例可满足的类型条件；数域未知、除数非零、指数合法性、维度/索引、测度可测性、几何退化条件等不得静默推断或偷偷进 theorem 参数。存在歧义时保留原样拒绝虚假通过。

## 2. 一次贯通跨领域常见数学对象与运算

不要把下列内容拆成等候用户批准的七个微型任务；在同一工程任务中多领域并行抽象、复用 Mathlib 类型、补齐实际 Lean lowering 与证明义务：

**代数/不等式/方程**：实数/复数/整数/有理数、代数式恒等式、多项式/有理函数、函数值、分式与根式、方程组、解集合、不等式、绝对值、定义域和非零条件、参数与条件分支。接 Mathlib 通用 Ring/Field/OrderedRing 与实际引理（例如 `ring`、`linarith`、`nlinarith` 使用时证明义务仍来自用户的步骤）。

**数论/组合/离散结构**：Nat/Int 整除、同余、gcd/lcm/prime、有限集合、sum/prod、组合数、抽屉原理、递推、归纳、图论基础、计数及双射/注入/满射。能进行常见集合与数论证明，不是只显示运算名。

**线性代数**：Index/Fintype、`Fin n → α`、矩阵型、矩阵秩、可逆、行列式、迹、核/像、线性映射、子空间/子模、基/维数、线性相关与张成、内积/范数、特征值/特征向量，尽量复用 Mathlib `Matrix`、`LinearMap`、`Submodule`、`Module` 与 `Finsupp` 等既有对象。类型、域、维度与类型类证据严格来源明确；不能把 `Module K V` 默认为所有需要的额外加法类。

**数学分析**：极限、连续、导数、积分、数列/级数、收敛、单调与极值、区间、基本实分析命题，复用 Mathlib Filters/Topology/Continuous/HasDerivAt/IntervalIntegral/Summable 对象，不创建自相矛盾的影子定义。区别函数值、性质证明和需要的可微可测条件。

**欧氏/解析几何**：距离、角、点线、共线、平行垂直、三角形、圆、向量/坐标、仿射/内积空间、几何变换和证明常见关系；必须辨析图示观察与用户文字已知条件。优先复用 Mathlib EuclideanGeometry、Affine、InnerProductSpace、MetricSpace。

**概率/统计基础**：事件、概率空间、条件概率、独立性、随机变量、分布、期望与方差。正确使用 Mathlib MeasureTheory 的类型/概率实例/可测性/分母合法条件；不要把 P(A|B) 当作任意非零概率自动存在。

**抽象代数**：群/环/域/半群、同态、作用、Module、理想、商、抽象载体/结构类证据，支持来源明确的任意载体与多参数代数约束，通过泛型 Mathlib 声明/运算实现而非每种例子手写数学常量。

各领域优先覆盖最常用、实际可定义/可证明的组合，并逐一列出哪些是**数学表达与类型检查**、哪些已经完整下放到 Lean/Kernel；不允许将“能 import 一个库”作为该领域功能已完成的依据。

## 3. 通用证明结构扩建

用户原证明的每个局部步骤/前提都要被检验。扩充并**组合式支持**：直接论证、多步等式与不等式链、应用引理、等价双向证明、反证、逆否、分类讨论、存在引入/消去、唯一性、全称引入/消去、局部变量和局部假设、归纳（多基例/强归纳/结构归纳）、辅助引理、多个子目标与多路线汇合、嵌套作用域及依赖。ProofRoute/Scope 层使用通用结构而非每项证明方法各建独立且不能相互组合的流水线。

严格保留用户的原步骤和 `dependsOn`、来源 `SourceRef`、Kernel 的每步真实结论。没有用户证据的 ProofNode 不得由 AI 补写另一条正确路线来替代“原证明通过”。能生成另一种形式证明时需明确区分“建议/修复”与“原证明已核验”。

# 极简 Lean｜Native 通用数学文档与复杂证明结构主体功能

日期：2026-10-16。基线：`725b5ce`。开发工作树：`/[LOCAL_USER]/Documents/ChatGPT/极简lean-native-math-document`；分支：`codex/native-math-document-engine`。本任务由 ChatGPT 独立进行，避开 Codex 同时修改的 MathIR / Compiler / TypeChecker。

## 真实缺口及影响

旧 `MathText` 的核心展示路径只对部分分式、根式、脚本单行式做本地排版，`MathPresentation` 支持有限的命令替换；`\begin{matrix/cases/aligned/array}`、多行推导、带索引求和积分、复杂定界符不具备通用的原生结构化布局。公式按钮已有但编辑缺少直接的排版预览。V2/V3 ProofRoute 的局部假设、嵌套作用域、归纳元数据及多条路线主要被平铺成步骤，难以让用户理解原证明结构。

## 本轮实际实现

- 新增 `NativeMathDocumentSyntax.swift`：纯 Foundation、只读、保留原稿的 TeX 解析 AST；支持嵌套分数、组合上下标、可选开方指数、和式/积式/定积分范围、数学黑板字体/书法字体、常见逻辑/集合/线代/分析运算符、\left/\right、二项式、重音符、矩阵/行列式/array、cases、aligned/align/alignat/equation/gather/multline/split/gathered 等环境及其单元格、段落与 display / inline math。未闭合、来源不完整或未知命令时返回未经修改的 TeX 文本；不解析输入为 MathIR、不猜数域、不执行 Lean。
- 新增 `NativeMathTypesetting.swift`：真正的 SwiftUI 原生公式结构渲染；分式、根式、上下标、矩阵/分段函数网格、长公式水平滚动、比例可伸缩括号、多行 aligned 推导。支持 VoiceOver 原公式与菜单复制原始 TeX；普通段落尽量保持选择与自动换行，调用方已有 `horizontalScrolling` 属性继续有效。
- `MathText` 接通新文档引擎，旧 `NativeFractionLine` 与 `MathPresentation` 作为兼容回退保留。没有引入 WebView、HTML/JS 渲染、云端 KaTeX 或新费用。
- 新增 `NativeMathDraftPreview.swift`，接入工作台与修改证明页面的可选本地实时数学排版预览。编辑器来源字符串保持不变，不自动发 DeepSeek、MathIR 或 Lean，只有用户原有主动验证操作才提交数学任务。
- 新增 `NativeProofStructure.swift` 及 `NativeProofStructureView.swift`，从 V3 `proofRoutes[].nodes` / `inductions` / `scopes` 和已有保存核验记录建立只读多路线/局部假设/归纳阶段/分支对应。仅复杂证明显示额外的结构视图，不替换原有逐步证据。保留 route-local node ID 到复合 step ID 的映射，显示丢失依赖/异常 scope；整体 Kernel 通过严格遵从原 `ProofRecord.verified`。
- Native `NativeMathIRContext.expression` 增加对 Codex 正在扩建的 `mathlib_const` 来源声明名的显示。仍不把该常量当成已在 Lean 检查通过的来源证明。
- 新增 `tests/native_math_document.swift`、`tests/native_proof_structure.swift` 和串行开发测试入口 `scripts/check_native_math_document.py`。测试只验证真实 Swift 代码的数据/结构/呈现模型，并非真实 DeepSeek 或 Kernel 证明 E2E。

## 数学语义可信边界

- 排版器是显示工具：不重写数学输入、不更改 MathIR、Statement Lock、类型约束、证明路线、Kernel/Repair、用户历史数据。
- 解析失败保持原源码；识别/公式翻译/MathIR 的语义忠实度不因此改变。
- 归纳图中的节点、步骤证据都来自保存字段；节点局部核验成功不等于整条原证明路线通过。中断后的 `partial` 不冒充最终通过。
- `mathlib_const` 字段为当前 Codex 活跃工作树中的进行中契约，如后端随后调整其名称或签名，应基于实际提交进行安全对齐。

## 后续主体功能：原生数学原稿编辑器（同一开发分支接续）

原先编辑工具栏中的公式按钮只增加临时 AppKit 富文本视觉属性，不能真正插入数学源代码；符号速查只提供复制操作；修改证明页面使用独立的 SwiftUI TextEditor，缺少与工作台一致的插入与选区能力。

本轮将通用排版扩展为可实际编辑的数学文档系统：

- 新增 NativeMathEditorCommands.swift：纯 Foundation 数学编辑动作，提供行内/独立公式、分式、根式、上下标、组合数、求和、连乘、积分、极限、矩阵、行列式、分段函数、对齐推导、集合、范数、向量的可编辑模板。对当前选区包裹原有数学原文，无选区时选中第一个可编辑参数。
- 统一使用 UTF-16 NSRange，拒绝越界和半个 Unicode 代理对的编辑范围，避免包含 Emoji 的数学原稿被误截断。
- 命令使用唯一身份及一次性消费引用对象，防止 SwiftUI 重新构建 AppKit 编辑器时重复执行此前的公式插入。
- NativeDraftEditor 通过真实 NSTextView.insertText(replacementRange:) 执行，保留 macOS 原生撤销/重做和光标。工作台原有公式按钮现在执行真实 TeX 插入，符号面板在可编辑时直接插入，非编辑状态仍支持复制。
- 新增 NativeMathSnippetPalette.swift：分类与搜索数学公式组件。工作台和修改证明页统一采用 AppKit 数学编辑器及可选本地实时排版预览。
- 插入模板是用户主动操作产生的可编辑示例，不是 AI 推导出的数学事实，不会自动添加数学前提、请求 DeepSeek 或执行验证。

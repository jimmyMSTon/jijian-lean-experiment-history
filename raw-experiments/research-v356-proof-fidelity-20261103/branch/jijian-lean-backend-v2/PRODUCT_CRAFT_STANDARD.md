# 极简 Lean｜macOS 产品品质规范 V1

**确认时间：2026-10-09。** 用户明确要求将 Apple 级产品品质纳入既有工程推进与体验检查。

**适用范围：** macOS 原生 SwiftUI/AppKit 客户端的界面、交互、数学排版、文案、性能、稳定性和分发体验。Lean/MathIR/DeepSeek 等底层功能的已确认逻辑保持不变。

**性质：** 这是已经确认的品质方向和现有工作中的审查基准；不自动增加产品功能、数量限制、性能数值阈值、测试 Gate、发布条件、验收阻塞、审批步骤或独立工作流。具体涉及产品行为改变的建议，标出影响后由用户确认。

## 产品气质

- **原生：** 使用真实 macOS 窗口、系统控件与菜单行为，不造假的窗口按钮或系统提示。
- **克制：** 数学原稿与证明始终是视觉中心，避免开发者后台式堆叠。
- **轻快：** 反馈及时，切换、编辑、滚动不无谓等待；性能问题基于实测定位，不擅设时间指标。
- **可信：** 严格区分 Kernel 已验证、尚未证明、形式化失败、识别问题、网络/服务错误。

## 在现有开发与 QA 流程中检查的品质维度

1. **原生窗口与系统行为**：红黄绿窗口按钮、窗口拖动、缩放/全屏、菜单栏、快捷键、系统文件对话框、拖拽、触控板操作。优先系统机制；SwiftUI 为主，确有需要局部 AppKit。
2. **视觉一致性**：全局字号、行高、数学字体、间距、对齐、图标、圆角、分隔、焦点与按钮状态。减少重复工具栏、卡片和工程标签；尊重已有 Stitch/SwiftUI 确认设计，不擅改风格。
3. **数学排版**：公式基线、行间与行内公式、分数、求和、积分、括号、上下标、矩阵、长式换行与文本选择；中文与数学符号混排必须可读。
4. **交互细节**：键盘焦点、选取、复制粘贴、撤销/重做、鼠标悬停和按下反馈、长证明滚动、返回与编辑后重新验证；操作应符合 macOS 习惯。
5. **速度与资源表现**：打开窗口、编辑响应、翻页/页面切换、长文档滚动、内存/CPU、网络等待状态；记录实际异常和证据，不凭空设定数值门槛。
6. **稳定与恢复**：导入出错、识别歧义、Lean/AI 异常、取消任务、窗口关闭或休眠后状态；不得丢失原稿或把系统失败误报为数学错误。自动保存/恢复策略如涉及新行为，先征得用户确认。
7. **中文文案与信息层级**：简短、自然、专业、学术语感；不使用夸张 AI 文案，不为普通用户常显模型名、MathIR、Lean diagnostics、Token、后台“已启动”等工程状态。具体措辞以用户确认文本为准。
8. **无障碍与系统适配**：键盘可操作、VoiceOver 可理解、焦点顺序、文本尺度、对比度；结果用文字/图标加颜色表达，不只靠红绿。
9. **分发与信任**：App 名称、图标、Dock、关于窗口、版本、相机授权时机、用户数学内容何时上传、签名/公证及安装体验；本机开发签名不等同正式分发完成。

## 原证明验证的特殊真实性要求

- “Kernel 通过”仅表明固定的 Lean 形式命题被验证，不自动代表 OCR/MathIR 与原图逐字一致。
- 原文每一步的红绿状态必须来自真实步骤级证据，不能把整题成功或 fixture 成功投射到所有行。
- 未得到证明、形式化失败与数学反例的 UI 说明应区分；不得因成功样式好看而伪造结论。
- 展示顺序优先“原证明 → 当前结论/问题步骤 → 用户可理解的依据”；原始 Lean 信息只在已有高级入口按需展开。

## 执行方式（嵌入当前流程，不新增 Gate）

在已有 UI 任务、截图核对或功能审计里，关注：
- **真实画面与操作**：优先正式 SwiftUI App 截图、窗口实际操作；fixture 只证明表现，不能代替实际业务结果。
- **可追踪问题**：记录页面/状态、现象、截图或操作证据、与确认设计的差异、建议修复和对产品行为的影响。
- **最小变更**：可直接处理不改变产品行为的表现 Bug；新增功能、默认开关、限制、数据逻辑或行为变化先请用户确认。
- **复核说明**：如有修复，在已有报告中注明“已实测/仅预览/尚未核对”，不包装为已全面完成。

**本规范没有独立上线门槛或数字评分线。** 未定义事项均为建议；用户最新明确指令优先。
